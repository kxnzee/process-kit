# Создание адаптера копированием

Скопируй всю папку adapters/example/ в adapters/<имя>/; не копируй только фрагмент
текста из инструкции. Имя каталога и область записи выбери по
[модели владения](../../docs/ownership.md#имена-определений). Не перезаписывай существующий адаптер.

```text
example/
  ADAPTER.md
  README.md
```

ADAPTER.md — описание подключения, которое читает исполнитель. Этот README —
пояснения автору при создании. При расширении дополнительные материалы остаются
в той же папке и явно связываются с ADAPTER.md; пустые папки создавать не нужно.

## Что изменить в копии

1. Название системы и kind; удалить учебное название Example System.
2. Тип подключения: taskStores/taskStore либо codeStores/codeStore.
3. Сопоставление возможностей с реально объявленными инструментами. Не переносить
   учебный readRecords в рабочую настройку как будто он существует.
4. Входы, ответы, поля, нормализацию, пагинацию, лимиты и ошибки каждой операции.
5. Статус проверок: непроверенное оставить явно непроверенным.
6. В выбранной записи config/ указать adapter: adapters/<имя>/ADAPTER.md,
   реальный kind и mcpServer. Токены в эти файлы не записывать.

## Разделы и свойства

| Элемент | Обязательность и назначение |
|---|---|
| Название / kind | Название системы и её технический тип; kind согласован с выбранной записью подключения, это не kind экшена source/transform/act |
| MCP-сервер | Источник — mcpServer выбранной записи; имя сервера не зашивается в адаптер |
| Capability | Назначение операции, согласованное с capabilities подключения |
| Инструмент | Реально объявленное имя и подтверждённая схема; учебное имя не разрешает вызов |
| Тип операции | read или write; write требует экшена act и согласия на конкретное изменение |
| Вход | Обязательные/необязательные параметры, типы, допустимые значения, источники и defaults |
| Результат | Поля и типы ответа, идентификаторы, полнота и подтверждение внешнего изменения при записи |
| Пагинация | Признаки продолжения, конца, размер страницы и усечение; если не применяется, объяснить почему |
| Нормализация | Соответствие полей API контракту экшена, даты, статусы и отсутствие данных |
| Ограничения / ошибки | Реальные лимиты, права, ограничения фильтров, причины остановки и условия допустимого повтора |
| Пробный прогон | Только явно выбранные демоданные; без внешних вызовов и утверждений о живой системе |
| Статус проверок | Что подтверждено, дата/среда и основание; непроверенное отмечается отдельно |

## Граница адаптера

Адаптер объясняет, как использовать конкретную систему. Он не выбирает бизнес-задачу,
не содержит SDD-условий, формул, отчётных шаблонов и маршрута процесса. Запрос и его
аргументы получает экшен от процесса. Адреса, репозитории и проекты — в выбранной
записи подключения, секреты — в хранилище клиента.

## Проверка

`node tools/kit.js check --only adapters` проверяет структуру описания.
После подключения копии: `node tools/kit.js check --only connections` и preflight
вызывающего процесса. Проверка файлов не подтверждает существование инструмента
или доступность API; живую проверку отмечай отдельно только после её выполнения.
