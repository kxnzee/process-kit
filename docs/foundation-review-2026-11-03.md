# Доработка основы исполнения — 03.11.2026

Ветка: `codex/reviewed-before-v2`. Изменения подготовлены локально, без публикации.

## Что исправлено

1. **Вложенные процессы.** Журнал сохраняет стек вызовов, параметры и артефакты родителя. Команды `enter` / `leave` возвращают исполнение к следующему шагу родителя. Завершить корневой запуск на конце дочернего процесса нельзя. Проверяются также хеши результатов уже завершённых дочерних шагов.
2. **Защита коммита.** Установщик добавляет pre-commit вместе с pre-push. Проверка читает подготовленный Git-индекс, блокирует распознаваемые секреты, буквальные доступы в settings.json и локальные результаты. Значения секретов не печатаются; прежние пользовательские hooks сохраняются. Это ограниченный детектор известных форматов, не доказательство отсутствия любых секретов. При заданном core.hooksPath установщик прекращает работу с объяснением.
3. **Контракты результатов.** Каждому экшену задан контракт: JSON-схема поддерживаемого подмножества либо непустой текст. Журнал проверяет результат до сохранения успешного шага. Для SDD дополнительно проверяются идентичность выборки, состав ключей, непересечение групп, счётчики и процент. Это структурные проверки; достоверность внешних фактов и качество текста остаются отдельной проверкой.
4. **Зависимости запуска.** Состав файлов вычисляется по процессам, дочерним вызовам, экшенам, выбранным запросам, правилам, шаблонам, схемам и используемым подключениям. Агенту не нужно вручную составлять обязательный список. Служебный код сохраняет состояние и проверяет контракты; решения и выполнение экшенов остаются у GigaCode.

## Проверки

`node tools/check-all.js` завершился успешно. Добавлены 20 проверок основы исполнения и 9 проверок защиты коммита; существующие проверки также прошли. `git diff --check` не обнаружил ошибок.

Валидатор выдал одно ожидаемое предупреждение: техническое имя ветки `codex/reviewed-before-v2` не задаёт код команды. Для проверки конкретного командного слоя требуется `--team <код>` либо настройка `processkit.team`; сценарии командных веток отдельно входят в набор проверок.

Проверены trace, state, два артефакта и запись истории с outcome `draft`: стек пуст, курсор вернулся к родителю, оба шага завершены. По журналу команд агент использовал инструкции и шаблоны, выполнил адресную валидацию процесса и команды run-journal. Тестовые наборы и эталоны при обычном выполнении не использовались. В начале прогона были две бытовые ошибки оболочки (зарезервированная переменная `status` и поиск ещё не созданного outputs); они не затронули исполнение процесса.

## Что остаётся на приёмку

Нативный прогон в GigaCode, реальные ответы настроенных MCP и проверка внешних операций пользователем. Локальные проверки и изолированный сценарий этого не заменяют. Новые hooks начинают действовать в конкретной копии после `node tools/install-hooks.js`; сам факт наличия файлов в репозитории их не устанавливает.
