# Личные настройки и инициализация

Модель веток и доступа — [ownership.md](../../docs/ownership.md). Ниже описан формат и применение данных этого каталога.

EXAMPLE.json показывает полный набор полей, которые может заполнить rk-init.
Это заготовка с TODO, а не готовый рабочий конфиг. Скопируй её в config/my/config.json
и материализуй только нужные части. Не переносить командные записи в личный слой.

| Поле | Что делает инициализация |
|---|---|
| schemaVersion | Оставляет 2 |
| profile.name / email | Сохраняет подтверждённую локальную Git-идентичность; не выдумывает и не читает глобальные секреты |
| teamId | Выбранный team.id, либо null при ответе «Без команды»; название команды хранится в team |
| storage.mode | local — только компьютер, repository — собственный репозиторий |
| storage.repositoryUrl | Только при repository: подтверждённый адрес remote mine, отличный от origin; при local поле удаляется |
| taskStores / codeStores | Только собственные подключения; структура показана полностью, id my-tasks/my-code можно изменить |
| defaults.taskStore / codeStore | Выбор по id личной или командной записи, без копирования самой записи |
| defaults.project / repository | Необязательный выбранный ресурс; repository имеет вид projectKey/slug |
| preferences | Только уже согласованные переносимые предпочтения; при инициализации допустим {} |
| preferences.addressAs | Необязательное обращение в чате: точное имя/ФИО либо null для общения без имени |
| preferences.addressMode | formal — на «вы» (по умолчанию), informal — на «ты» |
| preferences.responseDetail | auto — по задаче (по умолчанию), brief — кратко, detailed — с объяснениями |

`profile.name` хранит подтверждённое имя/ФИО для подписи Git. При новой настройке
инициализация предлагает имя и почту из Git и даёт исправить их; глобальный Git-конфиг
не меняется. Для обращения можно выбрать другое написание:

```json
{
  "preferences": {
    "addressAs": "Алексей Викторович",
    "addressMode": "formal",
    "responseDetail": "brief"
  }
}
```

Обращение используется умеренно и только в чате. Поле отсутствует или равно null —
агент общается без имени. Оно не обязательно для готовности личной копии; прежние
конфиги с preferences={} продолжают работать. Пожелание «называй меня Алексей» меняет
только addressAs, сохраняя подпись Git и другие настройки.

Все три поля необязательны. При настройке можно одним ответом выбрать «Алексей,
на ты, коротко» или пропустить выбор. Позже постоянные пожелания «давай на вы» и
«отвечай подробнее» меняют только соответствующее предпочтение. Разовая просьба
«сейчас коротко» важнее настройки для текущего ответа, но не сохраняется.
Краткость не убирает существенные факты и препятствия. Настройки стиля действуют
только в чате; требования к отчётам и выполнению процессов задаются отдельно.

## Что заполняется всегда

Выбранная команда/отсутствие команды, подтверждённая идентичность пользователя и
вариант хранения. Локальные настройки Git выводятся из этих значений и сверяются
с ними, но не являются вторым источником выбора. Абсолютные пути checkout не сохраняются.

## Что заполняется по необходимости

При personal-only не запрашиваются будущие подключения: удали обе учебные записи,
оставь taskStores/codeStores=[] и defaults={}. Не оставляй TODO вместо выбранной команды
или storage.mode. При live заполняй только нужные личные подключения; если используются
командные, личные массивы остаются пустыми, а defaults ссылаются на командные id.
Неиспользуемые поля defaults удаляются. Учебные подключения не включаются автоматически.

При смене default-подключения прежний командный default его ресурса не наследуется.
teamId=null отключает командный слой. Чужой id команды и повтор id подключения — ошибка.
Файл не переносится в team/master. Параметры соединений описаны в
[настройках команды](../team/README.md). Секреты хранятся в клиенте.

## Настройки одного процесса

`processes/<имя процесса>/config/my.json` задаёт значения параметров одного процесса:
выбранное подключение, период, периметр КЭ — что процесс объявил в `params` своего
PROCESS.md. Уровни различаются именами файлов: master.json, team.json, my.json.

Читаются только уровни из `requires.config`; пустой список не читает ни один файл.
Выбор команды и исключение командного слоя выполняет общий resolver конфигов.
Личный конфиг не влияет на процесс, если `my` не объявлен. Основные конфиги выбранных
уровней, определяющие этот выбор, также входят в снимок запуска.

```json
{ "taskStore": "my-releases-sigma", "startDate": "2026-11-09" }
```

Неизвестное имя параметра и файл процесса, которого нет, — ошибка проверки, а не молчаливое
игнорирование: настройка не должна выглядеть рабочей, когда она ни на что не влияет.
Значение файла ближнего уровня важнее `params` из PROCESS.md и дальнего уровня (личный
перебивает командный, командный — общий), а явный аргумент человека или параметр
вызывающего процесса важнее любого такого файла. Файл входит в снимок прогона: изменить его
посреди прогона нельзя, шаг остановится с «Изменён вход». Личные файлы в team/master
не переносятся.


### Перенос прежних настроек

Старый `config/<уровень>/processes/<имя>.json` продолжает читаться, пока нового файла
того же уровня нет. `config --process <имя>` показывает такие файлы в `legacySettings`.
На файловой системе без учёта регистра миграция сохраняет фактическое написание
прежнего расширения `.JSON` в журнале для точного отката; активный Run блокирует
перенос независимо от регистра пути в его снимке.
Два файла одного уровня — ошибка: не выбирайте один молча. Удаления старого формата
в этом выпуске нет. Приоритет, `requires.config`, исключение чужой команды, проверка
имён параметров и секретов остаются прежними. Новые файлы создавайте в папке процесса.
Настройки не входят в допуск публикации определения; в снимок конкретного Run входят.

Из корня своей рабочей копии выполните предварительный просмотр:

```sh
node tools/kit.js config --migrate-process-settings
```

Команда проверяет только текущий подтверждённый уровень master/team/my, существование
процесса, допустимость параметров и отсутствие конфликтов. Она не исполняет JS
определений. При `ready=false` исправьте перечисленные препятствия. Не начинайте новые
Run во время переноса или отката. Активный Run с этими настройками и повреждённое либо
неизвестное состояние Run блокируют перенос; завершите его на прежней версии.

```sh
node tools/kit.js config --migrate-process-settings --apply
node tools/kit.js config --rollback-process-settings <идентификатор-журнала>
```

`--apply` переносит содержимое побайтно, не перезаписывая существующие файлы. Проверенные
значения сохраняют приоритет, меняется только путь их происхождения. Идентификатор
журнала возвращается в результате. Журнал в `.history/process-settings-migrations/`
содержит пути и хеши без значений. Повторный перенос не создаёт дубликатов. При сбое
используйте указанный журнал для отката, включая частично перенесённые файлы.
Откат допускается только в той же области владения и при неизменённых значениях.
Если файлы уже правили, автоматический откат остановится, сохранив обе версии.
После переноса проверьте diff и `node tools/kit.js check`, затем `config --process <имя>`
для используемого процесса. Сохраняйте только свои точные пути; личный `my.json`
нельзя отправлять в командный или общий уровень.
