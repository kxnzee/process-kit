# Инструменты и внутренние модули

Единственная публичная точка входа: `node tools/kit.js --help`.
Машинный каталог: `node tools/kit.js --json`. Каталог содержит назначение, аргументы
и характер изменений каждой команды. Реестр находится в kit.js; отдельный список
скриптов агенту собирать не нужно. Прежних путей и совместимых обёрток нет.

## Выбор команды

| Задача | Команда |
|---|---|
| Найти сущности, темы контекста и подключения процесса | entities |
| Сохранить шаги и результат процесса | run |
| Посмотреть настройки и причины отсутствия подключения | config |
| Проверить структуру или готовность процесса | check |
| Запустить тесты при разработке | test |
| Установить защиту локального Git при настройке | hooks-install |
| Получить план переноса изменений | promote-plan |

Обычный исполнитель использует entities и run, а check — для предпусковой проверки.
Test не входит в рабочий запуск. Hooks-install меняет локальные hooks Git, run пишет
состояние и результаты; остальные команды читают данные. Promote-plan не копирует,
не коммитит и не отправляет изменения. Согласия на внешние действия не выводятся
из наличия команды. Инструкция исполнителю находится внутри его SKILL.md.

## Решение по каждому прежнему файлу

Все перечисленные файлы сохранены как внутренний код в tools/lib/, а не как отдельные
инструменты для выбора агентом. Ни один из них не является тестом. В таблице указана
конкретная задача и основной потребитель.

| Группа / файл | Зачем нужен и кто использует |
|---|---|
| actions/action-runtime.js | Загрузка runtime из сущности экшена; журнал, зависимости и проверка артефакта |
| actions/action-support.js | Аргументы, ресурсы и подключение источника; runtime экшенов |
| actions/query-file.js | Проверка пути и владельца запроса; исходные экшены и конфиг |
| actions/query-data.js | Связь отбора selectionId и демо-выборка; run-query и потребители отбора |
| actions/code-data.js | Демо-свидетельства кода для выбранных ключей; read-code-evidence |
| config/config.js | Разрешение уровней и выбранных подключений; config, entities, runtime |
| config/config-contract.js | Схемы конфигов; загрузчик конфигурации |
| contracts/artifact-contract.js | Проверка выхода экшена перед save; журнал |
| contracts/value-contract.js | Проверка JSON-схем и значений; контракты и runtime |
| core/markdown.js | Разбор шапок сущностей; загрузчики и валидатор |
| core/paths.js | Корень Git, имена запусков и результатов; журнал и Git-защита |
| core/safe-path.js | Границы файловых путей и запрет symlink; загрузчики и журнал |
| entities/entities.js | Декларации и манифест сущностей; entities и журнал |
| entities/context.js | Каталоги тем и доступ к уровням; манифест, ресурсы, валидатор |
| entities/process-model.js | Модель шагов, переходы и уровни; журнал, зависимости, валидатор |
| entities/process-dependencies.js | Снимок зависимостей и параметры шагов; журнал, манифест, валидатор |
| runtime/run-journal.js | Состояние запуска и запись результатов; run |
| runtime/history.js | Индекс завершённых запусков; только журнал, отдельный CLI удалён |
| git/install-hooks.js | Установка локальных hooks; hooks-install |
| git/commit-guard.js | Проверка индекса перед коммитом; pre-commit hook |
| git/prepush.js | Проверка отправки refs и назначения; pre-push hook |
| git/git-hook.js | Сохранение вызова прежних hooks, включая Windows; обе Git-защиты |
| git/promotion-plan.js | План переноса относительно общего предка; promote-plan |
| validation/validate.js | Структурные и предпусковые проверки; check |

Прежний tools/check-all.js перенесён в tests/run.js и вызывается через команду test.
Неиспользуемые wrappers outputs/runFolder/runFolderName/history/runsLog/cache и их
константы удалены из paths.js. Остальные модули имеют рабочие вызовы.

## Правило расширения

Новую публичную команду добавляй только для самостоятельной технической задачи,
которой ещё нет среди существующих команд. Укажи purpose, usage и scope в kit.js.
Общую реализацию клади в соответствующую группу lib/; её наличие не создаёт новую
публичную команду. Предметную операцию оформляй экшеном, ресурсы сценария — внутри
процесса. Тесты размещай в tests/, техническое описание — в docs/.

## Проверка Windows

.github/workflows/check.yml запускает полный набор на windows-latest и ubuntu-latest,
Node.js 22 и 24. Запуск автоматический для push/PR, также доступен workflow_dispatch.
CLI-тесты используют каталог с пробелами и кириллицей; проверяются запись результата,
установка hooks и вызов прежнего hook. Проверка имён устройств и Windows-ветки shell
входит в набор. Локальный успех на macOS не заменяет зелёный Windows job для нужного
коммита. Workflow проверяет опубликованный снимок, не незакоммиченные изменения.
