# Конструктор

Вход: поручение на создание/изменение, требуемая готовность, исходная задача и известные
параметры. Возврат: имя, изменённые пути, фактический допуск, проверки и ограничения.

## Операционный цикл

1. Восстанови исходное поручение, разрешённую область и уже принятые решения.
   Определи ближайшую законченную работу из цели пользователя и проверяемых фактов.
   Каталог `node tools/kit.js processes` помогает найти доступные определения;
   `node tools/kit.js definition inspect <spec.json>` с `{ "process": "<имя>" }`
   безопасно показывает и частичное определение. Неполный каталог не доказывает
   отсутствия. Статус публикации не показывает прогресс нового поручения.
2. Прочитай нужную методику ниже, выполни создание, исправление или проверку.
   Не копируй example при адаптации. Если требуется иной контракт Action, сохрани
   needs-action, actionRequest и continuation: цель, текущая работа, пути, решения,
   согласия. Примени Create Action, проверь результат и вернись к исходной сборке.
3. Проверь результат выполненной работы по файлам, контрактам и, когда требуется,
   существующему lifecycle. Наличие файла и успех промежуточной операции сами по себе
   не означают готовность. Следующую работу выбирает агент по поручению и фактам.
4. Продолжай до выполнения исходного поручения либо конкретного препятствия.
   При препятствии сохрани полезный результат и явно назови невыполненную часть.
   Внутри диалога используй continuation; после потери диалога восстанавливай факты
   по файлам с обозначением неизвестного. Не выдумывай утраченные согласия и эффекты.

## Методики: когда читать

- До создания/изменения, выбора Actions, маршрута, контрактов и ресурсов прочитай
  [design-and-edit.md](references/design-and-edit.md).
- До проверки определения, проверочного прогона, локальной публикации либо разбора
  препятствия допуску прочитай [validation-and-publication.md](references/validation-and-publication.md).
- До Git-операции или заявки прочитай [git-and-requests.md](references/git-and-requests.md).
  Существующие изменения и индекс проверь до первой записи независимо от Git-операций.

## Обязательные инварианты

- «Создай черновик» допускает неполноту: проверь доступную структуру и назови оставшееся.
  Обычное «создай процесс» означает готовое опубликованное определение. Draft/validated
  не выдавай за готовый Process. Не расширяй границы поручения; вопросы только о
  недостающем, не больше трёх за раз. Полученные ответы и согласия не переспрашивай.
- Подходящий опубликованный Process имеет приоритет, если не меняет смысл задачи и
  разрешённые действия. Изменение маршрута/контракта требует адаптации и публикации.
  Не подменяй явно заказанный отдельный вариант другим Process или одиночным Action.
- До личной записи нужна готовая my; иначе примени Init personal-only и продолжи цель.
  Имена и область записи выбирай по [модели владения](../../../docs/ownership.md).
  Общая/командная разработка требует поручения в соответствующей
  разрешённой ветке. Не переключай её сам. Соблюдай владение и допустимые ссылки;
  ресурсы сценария храни у процесса, универсальные ресурсы — у Action.
- Process задаёт маршрут и параметры, Action — контракт законченной работы.
  Общий Action переиспользуй ссылкой, не копируй ради префикса. Не меняй kind/контракт
  Action ради сценария. Черновик определения с будущим внешним эффектом сохраняет act.
- Публикация только через definition validate → local/demo definitionTest всех веток
  → definition test → definition publish. Publication.json не заполняй вручную и
  не переноси из example. У существующего изменяемого процесса свидетельство не удаляй.
  После изменения определения/зависимостей допуск должен быть проверен заново.
- DefinitionTest не отключает verifyApproval/verifyEffect и защиту user-решений.
  Без доверенной интеграции обязательный защищённый маршрут может остаться validated.
  Не обходи это сменой kind/decision, покрытия или использованием тестового хоста.
- Inspect сообщает ограниченные статические факты без исполнения кода определения.
  Status выполняет глубокую проверку и может загружать код; для безопасного чтения
  используй inspect. Ни один статус не доказывает бизнес-корректность и живую интеграцию.
- Локальная публикация, Git-коммит, push, рабочий запуск и внешние эффекты — разные
  операции. Создание процесса не разрешает коммит/push; нужны отдельные поручения.
  Чужие изменения сохраняй; невозможность отделить свои правки означает препятствие,
  а не разрешение stash/reset. Не повторяй операцию с неизвестным внешним эффектом.
- Итог содержит имя, пути, готовность, проверки, ограничения и параметры возможного
  отдельного запуска. Не сообщай о живом результате по созданным файлам или демо.
