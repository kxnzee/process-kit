# Установка локальных серверов доступа

Локальные серверы не входят в состав репозитория: в git лежат только их объявления в
`.gigacode/settings.json` и публичная команда проверки. На новой машине папки `.gigacode/mcp/bitbucket-mcp`
и `.gigacode/mcp/mcp-email` отсутствуют, поэтому клиент при запуске сообщает, что
`.gigacode/mcp/<имя>/dist/index.js` не найден. Эта операция ставит их.

Вход: корень копии проекта, путь к архиву (если он есть) либо указание собирать из исходников,
наличие Node.js. Возврат: `status=completed/blocked/failed`, какие папки появились, результат
проверки запуска и список шагов, которые остаются человеку (значения почты, секреты, перезапуск
сессии). Секреты в возврат не попадают.

## 1. Проверить готовность машины

```bash
node -v
```

Нужен Node.js 22 или новее; ниже — остановка, серверы не запустятся.

Проверить свободное место на диске копии: распаковка занимает около 250 МБ плюс временные файлы
сборки. Свободно меньше 1 ГБ — остановка со словами, сколько требуется и почему; не начинать
распаковку «авось влезет»: неполная распаковка оставляет полурабочую папку, а переполненный диск
ломает и клиент, и рабочую копию.

## 2. Проверить объявления подключений

В `.gigacode/settings.json` должны быть секции `pp-ai-bitbucket`, `pp-ai-email` и `pp-ai-onework`.
Если их нет, настройки в этой копии нет — так и сказать и предложить сначала доставить её,
самой себе подключения не выдумывать.

## 3. Поставить серверы

Основной путь — архив, который человеку передали вне репозитория: сетевая папка, переданный каталог,
вложение на внутренней странице. Путь к файлу называет человек.

Архив в репозиторий не кладётся и под другим расширением в него не переносится: серверная проверка
приёма изменений отклоняет отправку с архивами, и обходить её подменой имени — значит протаскивать
в общий уровень то, от чего она защищает. Поэтому источник один: файл передали руками, не клонированием.

Распаковать содержимое в папку `.gigacode\mcp\` копии так, чтобы появились папки серверов:
`bitbucket-mcp\` и `mcp-email\`. Проверка поставляется в tools/kit.js mcp-check.

Если эти папки уже есть, молча их не перезаписывать: показать, что именно существует, и спросить,
заменять или отменить. Существующая рабочая установка дороже нового набора файлов.

Запасной путь, когда архива нет, а исходники серверов доставлены в копию: в каждой папке сервера
выполнить по одной строке, порядок такой — сначала установка зависимостей, потом сборка.

```bash
npm ci --no-audit --no-fund
```

```bash
npm run build
```

Требует доступа к npm-реестру. Ошибка 401 или 403 при установке — вопрос к настройке реестра,
а не к учётной записи человека: не менять ничего вслепую, а показать текст ошибки.

## 4. Проверить запуск

Из корня копии проекта:

```bash
node tools/kit.js mcp-check --probe
```

Ожидается JSON со status=completed, двумя серверами status=ready и фактическим числом tools; код возврата 0. Число инструментов зависит от доставленной версии сервера.
Скрипт обращается к несуществующему адресам и работает с фиктивными значениями доступов — он про то,
что серверы запускаются, а не про то, что доступ есть.

## 5. Сказать человеку, что осталось за ним

Эти шаги не выполняются за человека и не проверяются до его ответа:

1. В секции `pp-ai-email` файла `.gigacode/settings.json` заменить заполняемые значения на свои:
   `USER` — табельный номер, `SMTP_FROM` — свой адрес, `LDAP_BIND_DN` — `<табельный>@sigma.sbrf.ru`.
2. Завести секреты: `bitbucket-inventory/BITBUCKET_TOKEN`, `mcp-email/PASSWORD`,
   `mcp-email/LDAP_BIND_PASSWORD`, для OneWork — `onework/Authorization`. Значения в файлы проекта
   не переносятся, в чат не присылаются, на экран не выводятся.
3. Перезапустить сессию клиента: переподключение без перезапуска инструменты уже запущенной сессии
   не добавляет.
4. Подтвердить доступ одним живым чтением каждого: `bitbucket_get_me`, `list_folders`, `search_ldap`.
   Готовность подключения подтверждается чтением, а не пунктом в списке. Отказ 401 или 403 — вопрос
   к праву доступа, таймаут сети — не повод менять токен.

Отдельно сказать, чего установка не делает: писем не отправляет, данных во внешних системах не
меняет, `.env` не создаёт.

## Границы

Менять разрешается только содержимое `.gigacode\mcp\` этой копии; глобальные настройки клиента,
чужие папки и файлы вне проекта не трогаются. Файлы серверов в git не добавляются: зависимости
игнорируются, архивы отклоняет серверная проверка, а 74 МБ бинарного содержимого в истории остаются
навсегда, даже после удаления файла.

## Частые отказы

| Сообщение | Причина и действие |
|---|---|
| `Cannot find package 'dotenv'`, `Cannot find module 'kerberos'` | зависимости потеряны или распаковка не завершилась: дочитать архив целиком либо выполнить шаг 3 запасным путём |
| `Bitbucket credentials не заданы` | нет `BITBUCKET_URL` или секрета токена |
| `Отсутствует или некорректная конфигурация: USER, PASSWORD` | заполняемые значения почты не заменены или секрет не заведён |
| сервер в списке подключений есть, инструментов в сессии нет | перезапустить сессию; у фонового агента набор инструментов пополняется отдельно |
| `ENOSPC`, «недостаточно места» | диск переполнен: остановить операцию, освободить место и начать заново, полураспакованную папку удалить целиком |
