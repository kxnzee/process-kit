# Контекст master / team / my

Контекст хранит термины, факты предметной области и содержательные правила. Конфиг
хранит идентификаторы, подключения и настройки. Инструкции поведения скиллов и
контракты экшенов находятся у владельцев, а не в автоматически читаемом контексте.

- master — общие сведения; доступны процессам всех уровней.
- team — сведения выбранной команды; доступны её team-процессам и наследующей my.
- my — личные рабочие сведения; доступны личным процессам.

В каждом уровне есть копируемая папка example/. Контекст: <уровень>/<тема>/CONTEXT.md.
Префиксы team- и my- у тем не нужны: владельца обозначает папка. Пример не является
рабочим контекстом и не загружается. Проверка: node tools/kit.js check --only context.

Процесс объявляет целые уровни: requires.context: [master, team, my]. Загрузчик
возвращает отдельный каталог тем каждого уровня; examples исключены. Полный каталог
попадает в снимок зависимостей, но читать все темы в модель не требуется: выбирай
нужные по задаче. Общий процесс не получает team/my; личный может объявить все три.
Аргумент экшена styleFile указывает точную тему внутри уже объявленного уровня.
Один файловый аргумент без объявления уровня не даёт доступ к контексту.

Контексты не сливаются по приоритету. При противоречии назови конкретные сведения и
источники и запроси решение для затронутой работы; не заменяй факты личным текстом молча.
Наличие папки не разрешает автоматически подмешать её в пакет каждого шага.

В my.preferences конфига — структурированные настройки (например, выбранный язык).
В context/my/<тема>/ — развёрнутые факты, словарь и правила подготовки содержания.
Одно пожелание не записывается сразу в оба места. Личные материалы не переносятся
в team/master. Командные наследуются из team-ветки. Смена команды не подменяет их автоматически.
