# Действие: прочитать таблицу оценок сотрудников

Один шаг процесса. Разбирает сводную таблицу GigaCode Maturity Index в предсказуемую форму:
по одному объекту на строку сотрудника. Ничего не пересчитывает и не оценивает — шкалы,
цель и рекомендации считает шаг расчёта. Сеть этому классу действий запрещена.

## Аргументы

- scoreFile — обязательный точный путь к файлу внутри репозитория (`.xlsx` или `.json`).
  Файл читается как есть, из чужих папок и из внешних ссылок шаг не берёт ничего.
- nameFile — необязательный точный путь к JSON-справочнику `"<табельный номер>": "<ФИО>"`.
  Нужен для старых снимков выгрузки, где колонки ФИО ещё не было: справочника людей по
  табельному номеру в подключённых системах нет (проверено живыми запросами). Если ФИО есть
  в самой таблице, справочник их не перекрывает.

## Что читается из таблицы

- идентификатор и окружение: номер сотрудника (столбец `Номер сотрудникА`, в свежих снимках —
  `ТН`), ФИО, название команды (`Команда`) и её код (`Код Команды`), тип команды, основная роль,
  область экспертизы, инициатива, признак целевой аудитории;
- блок «Обучение и применение»: число курсов, завершённых в срок, статус каждого курса,
  признаки целевого аудиторного курса, частота использования, режим работы, четыре балла блока;
- блок «Навыки»: планка по шести навыкам с флагом достижения, суммарный балл навыков,
  когорта потребления токенов и её балл, общий балл блока;
- блок «Продуктивность»: шесть метрик, у каждой значение, градация, отношение к медиане,
  сама медиана и балл; плюс строка про Story на сотрудника и общий балл блока;
- итог строки, квартили распределения, оценка в баллах перцентиля и справочные средние трайбы.

Имена столбцов сверяются по точным составным именам (`«Строки кода» , «Строки кода на коммит» ,
«Строки кода БАЛЛ»` — три разных столбца). Столбцы, которых шаг не знает, теряются не молча:
их число и имена попадают в `source.unknownColumns`.

## Рецепт исполнения

1. Файл разбирает код шага (`kit.js run execute`), свою разметку таблицы писать не нужно:
   для `.xlsx` — лист и общая таблица строк, для `.json` — массив строк или объект
   `{"headers": […], "rows": […]}`.
2. Отсутствие любого обязательного столбца — ошибка входа, а не пустое поле: без номера
   сотрудника строки нельзя отличить друг от друга, без баллов блока не проверить знаменатель.
   Остановка с именем отсутствующего столбца.
3. Пустое значение и `-` в ячейке — `null` и счётчик в `gaps`; это «в файле нет», а не «ноль».
   Числа принимаются и с точкой, и с запятой. Исключение — колонка ФИО: незаполненное имя
   считается в `names.matched`/`names.unmatched`, а не в пропусках, потому что это признак
   строки, а не недостающее число блока.
4. Строка без номера сотрудника в `employees` не попадает и остаётся в `skipped` с причиной.
5. Каждому числу соответствует ровно одна ячейка файла: шаг не выводит производные величины,
   не заполняет пропуски средним и не подбирает соседа вместо отсутствующего значения.
6. Вернуть `score-table` и проверить его контрактом `contracts/result.json`.

## Что в этом действии НЕ делается

- не читает Confluence, Jira, Bitbucket и портал — вход один, локальный файл;
- не считает доли, цель и рекомендации: это правило процесса, иначе форма отчёта начнёт
  влиять на методику;
- не угадывает ФИО: берёт колонку выгрузки, потом справочник владельца; если ни там ни там нет —
  остаётся табельный номер, и `names.source` честно говорит, что имён нет;
- не правит исходный файл и не создаёт его копий.
