Установленная версия GigaCode CLI или GigaCode Desktop

1 · Клонировать репозиторий

Необходимо установить git из SberUserSoft и выполнить команду git clone https://stash.sigma.sbrf.ru/scm/p4d/pp_ai.git rockit в любой папке.

Если нет прав на репозиторий, то обратиться к Бозюкову Артему Юрьевичу (AYBozyukov@sberbank.ru), в ближайшее время планируется репозиторий на InSourceHub_AI.

2 · Открыть папку проекта

Запустить GigaCode CLI в данной папке, либо запустить GigaCode Desktop и открыть папку проекта.

Проектные подключения к рабочим системам

В проекте есть проектные MCP-подключения: через них помощник читает Jira, Confluence, хранилище кода, почту и OneWork и записывает туда результат. Объявления лежат в .gigacode/settings.json вашей копии, а на месте токенов там ссылки вида $secret:<имя>/<ключ> — значений в файле быть не должно. Какие MCP-сервисы доступны в периметре и в каком виде (локально или сервисом) — основная инструкция «Агентские инструменты и сервисы».

Удалённым подключениям нужен только секрет; локальным серверам — ещё и сами файлы серверов, их ставит навык установки ниже.

Как подключить

  1. Поставить локальные серверы. Это делает служебный навык rk-install-local-mcp — его вызывает помощник по просьбе человека: достаточно сказать «установи локальные серверы доступа» и назвать путь к архиву. Навык проверяет Node.js и свободное место, распаковывает архив в .gigacode/mcp/ либо собирает серверы из исходников, проверяет запуск node tools/kit.js mcp-check --probe и называет шаги, которые остаются человеку. Доступы он не заводит и во внешних системах ничего не меняет.
  2. Заменить чужие значения учётной записи на свои — в секции pp-ai-email: USER — логин Sigma, SMTP_FROM — свой адрес почты. LDAP_BIND_DN остаётся ссылкой на секрет pp-ai-email/LDAP_BIND_DN; в клиенте за ней сохраняют <логин Sigma>@sigma.sbrf.ru.
  3. Завести секреты из таблицы — значения вводятся в GigaCode, не в чат и не в файл.
  4. Подтвердить подключения после окончательной правки настроек: агент показывает весь список проектных серверов и только после согласия на него выполняет из корня копии gigacode mcp approve --all. Подтверждения сохраняет сам клиент в пользовательском хранилище; агент вручную его файлы не редактирует. Правка секции сервера требует повторного подтверждения.
  5. Перезапустить сессию и подтвердить каждое подключение одним живым чтением из столбца «Чем подтвердить готовность»: готовность подтверждается чтением, а не пунктом в списке.

Заполняемые значения почтового подключения в секции pp-ai-email файла .gigacode/settings.json: логин сигма — логин вашей учётной записи Sigma, ВАШАПОЧТА — ваш адрес. Значения паролей в файл не записываются: на их месте ссылки вида $secret:, а само значение вводится в хранилище секретов GigaCode.

"USER": "<логин Sigma>",
"PASSWORD": "$secret:pp-ai-email/PASSWORD",
"SMTP_FROM": "<ваш адрес>@sberbank.ru",
"LDAP_BIND_DN": "$secret:pp-ai-email/LDAP_BIND_DN",
"LDAP_BIND_PASSWORD": "$secret:pp-ai-email/LDAP_BIND_PASSWORD"
