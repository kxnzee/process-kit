---
name: send-mail
description: Готовит и отправляет письмо по результатам предыдущих шагов после подтверждения человека
kind: act
adapter: none — в поставке почтового адаптера нет; черновик отдаётся пользователю текстом
consumes:
  artifacts: [report-text (или другой артефакт, по которому выполняется действие)]
  params: [to, subject]
produces:
  mail-draft: черновик письма, показанный пользователю
---

# Действие: выполнить действие по результатам

Один шаг процесса с внешним эффектом. Класс `act` всегда идёт последним звеном:
по артефактам предыдущих шагов готовится воздействие на внешний мир (письмо,
комментарий, тикет) и выполняется **только после явного «да» человека**.

## Рецепт исполнения

1. Собрать черновик: кому (`to`), тема (`subject`), тело из артефакта (например,
   `{report-text}` — путь к файлу артефакта шага-источника).
2. Получатели берутся ровно по `to`. Если `to` указывает на поле артефакта у группы
   задач («поле `responsible` у задач группы …»), взять это поле у каждой задачи, повторы
   убрать, пустые (`—`) пропустить, оставшиеся соединить через «; ». Имя человека без
   адреса остаётся именем: правдоподобный адрес вроде «имя.фамилия@…» не подставляется —
   письмо уйдёт не тому.
3. Пустой список получателей — не отправлять и не подставлять «кого-нибудь»: остановиться
   и спросить у человека, кому адресовать.
4. Показать черновик пользователю целиком, до отправки.
5. Без явного «да» внешний эффект не выполняется — ни «отправить чуть позже», ни
   «отправить копию себе», ни пересказ черновика вместо показа.
6. Адаптера для реальной отправки в поставке нет: честно сказать об этом и выдать
   черновик текстом для копирования. Когда владелец уровня добавит почтовый адаптер
   (`adapters/<система>.md` + запись в `config/sources.json`), рецепт расширится ссылкой
   на него — сам этот файл действия менять не придётся.
7. Вернуть `mail-draft` и статус: `черновик показан` или `отправлено (после подтверждения)`.

## Что в этом действии НЕ делается

- не выполняются повторные запросы к хранилищам: если данных не хватило, действие
  не «дотягивает» их само, а завершается с пометкой «не проверено»;
- не изменяется список получателей молча: любое отличие от `params.to` — только
  после отдельного согласия пользователя.
