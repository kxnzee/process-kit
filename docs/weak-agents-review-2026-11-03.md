# Исправления после прогонов слабых агентов

Ветка: codex/reviewed-before-v2. Два независимых сабагента gpt-6-luna с низким
уровнем рассуждения проверили текущие процессы в отдельных временных копиях.
Реальные GitHub/MCP и контур не затрагивались; Git remote — локальный bare-репозиторий.

## Что исправлено

1. Общая структурная проверка допускает TODO-адаптеры и TODO defaults.process
   незавершённой командной настройки. Отсутствующий конкретный адаптер/процесс
   по-прежнему ошибка. Preflight выбранного live-процесса требует заполненных полей:
   допуска к сети на основании успешной общей проверки нет.
2. Проверка уровней сравнивает унаследованные файлы с включённым в HEAD общим предком
   соответствующей remote-ветки. Изменение содержимого, режима и удаление блокируются;
   продвижение remote само по себе не делает закреплённую установку неверной.
   Личная настройка config/sources.json разрешена. Обычные различия окончаний строк
   checkout не считаются содержательной правкой. Сохраняются проверки новых имён.
3. splitFixture/normalizeFixture принимают явное имя выбранного запроса. Оно должно
   совпасть с fixture.query, включая my-/team-префиксы. Старый общий вызов совместим.
   Check-report берёт выбранное имя из query в fetch.json; чужая фикстура отклоняется.
   Чтение кода использует meta.query исходного отбора, не собственный sdd-evidence.
4. Обязательный demo-префикс «проба-» явно указан в контракте outputs и исполнителе.
   При ошибочном имени валидатор сообщает, как назвать папку. Сами условия валидатора
   demo/live не были противоречивыми: прежнее объяснение слабого агента было ошибкой.
5. Конструктору явно сказано: личный/командный процесс переиспользует общий экшен;
   новый префикс владельца не требует копирования действия.

## Проверки

Полный check-all: 144 сценария, все прошли. В том числе 20 проверок team-workflow,
23 проверки атомарности. Текущая служебная ветка даёт прежнее предупреждение о том,
что её имя не задаёт команду. Ошибок валидатора нет. Шесть скиллов прошли quick_validate;
git diff --check без замечаний.

Дополнительно найден и исправлен дефект самого нового теста: при запуске из настроенной
team/my-копии он включал её TEAM.md/sources в фиктивный master. Подготовка стенда теперь
отделяет общий снимок от персональных/командных материалов. Исправленный тест прошёл
также внутри временной командной копии слабого агента.
