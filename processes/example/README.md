# Копирование процесса

Выбери имя каталога и область записи по [модели владения](../../docs/OWNERSHIP.md#имена-определений).
Скопируй определение и ресурсы processes/example/ в выбранную processes/<имя>/, исключая publication.json. Если он уже перенесён,
удали только скопированное свидетельство в новой созданной тобой папке; исходное и
свидетельство существующего изменяемого процесса не удаляй. Переименуй name, title,
description и примеры запросов; задай свою область, версию и маршрут. Оставь
publication: required. У нового черновика свидетельства нет; для готового определения
создай его через definition validate/test/publish. Не оставляй учебное назначение в рабочем процессе.

Сначала переиспользуй экшены. Процесс задаёт аргументы, переходы и псевдонимы результатов;
операции выполняют экшены. Не копируй код экшена в PROCESS.md. Добавляй rules/, queries/,
templates/, renderers/ и contracts/ только когда они реально нужны этому процессу.

Учебный маршрут готовит черновик письма из исходного текста: редактирование → черновик.
Для локальной проверки передай start(inputText, params.to, params.subject, definitionTest=true),
затем выполни begin/save для обоих шагов и finish. Save использует attemptId из begin/next.
При копировании экшены edit-text и prepare-mail-draft остаются общими зависимостями.
Самостоятельный процесс создавай под пользовательский сценарий; обёртка ради выбора
входа и сохранения результата не требует отдельной сущности. Контекст подключён явно; не подмешивай другие уровни.

## Поля

| Поле | Обязательность и значение |
|---|---|
| `name` | Обязательно; имя папки процесса. |
| `version` | Обязательно; версия вида 1.0.0. |
| `area` | Обязательно; предметная область для выбора процесса. |
| `publication` | Только required (также значение по умолчанию). Legacy отклоняется; старую копию нужно проверить и опубликовать. |
| `branchRule` | Необязательный rules/<имя>.js, экспортирующий чистую choose({step, params, artifacts}) → {target, reason}. |
| `status` | Обязательно; статус применимости, например действует. |
| `title` | Необязательно; короткое название для человека. |
| `description` | Обязательно; назначение и ожидаемый результат простыми словами. |
| `example / examples` | Хотя бы один пример пользовательской задачи; строка / список строк. |
| `entry` | Обязательно; имя первого шага. |
| `requires.actions` | Имена целых экшенов из actions/. Все вызываемые экшены должны быть объявлены. |
| `requires.processes` | Имена целых подпроцессов из processes/. Все вызываемые подпроцессы должны быть объявлены. |
| `requires.context` | Уровни master/team/my; загрузчик возвращает каталог всех рабочих тем выбранных уровней, исключая example. Учитывается владелец процесса и выбранная команда. |
| `requires.config` | Уровни master/team/my, участвующие в выборе подключений. Загрузчик знает пути файлов и правила выбора. Для локального процесса пустой список. |
| `params` | Словарь параметров по умолчанию; явные параметры запуска имеют приоритет. |
| `Шаг: действие / процесс` | Ровно один вызов экшена либо подпроцесса; имя существующей сущности. |
| `Шаг: параметры` | Именованные значения; {params.имя} — параметр процесса, {артефакт} — путь к ранее сохранённому результату. |
| `Шаг: артефакт` | Псевдоним единственного результата функции в этом процессе; не обязан совпадать с produces. |
| `Шаг: следующий` | Имя следующего шага или end. Циклы и отсутствующие переходы запрещены. |
| `Шаг: decision` | code — вычисляет branchRule, model — предложение агента, user — защищённое продолжение с approval receipt доверенного хоста; без него разрешён только end корневого процесса. |
| `Шаг: branch` | Условия «когда: условие → goto: шаг» и обязательный default; решение фиксируется при исполнении. |

## Связанные файлы

Демо: `processes/<имя>/fixture.json`, только по явному dataFile. Готовые ответы не хранятся.
Глубина подпроцессов — по master.execution.maxProcessDepth (по умолчанию 5), без рекурсии. Общий процесс не ссылается на личные/командные сущности; между командами ссылки запрещены.
Сохранение прогона: `.gigacode/skills/pp-ai-run-process/SKILL.md`. Проверка: `node tools/kit.js check --only processes` и preflight `--process <имя>`.

## Разрешение сущностей

```yaml
requires:
  actions: [run-query, read-code-evidence, evaluate-data, compose-report]
  processes: []
  context: [master]
  config: [master, team, my]
```

Объявляй сущности целиком, без путей к внутренним файлам. Список может быть пустым;
неиспользуемые категории можно опустить. Имена в шагах должны быть объявлены.
Файлы запросов, правил, схем и шаблонов данного процесса принадлежат ему самому:
их не перечисляют внешними зависимостями. Шаги передают их функции точными аргументами.
Не перечисляй внутренние ресурсы экшена: они разрешаются по его ACTION.md и папке.

Команда `node tools/kit.js entities <имя> local` возвращает ready, entities, readFiles
и files. Для demo/live замени режим; при аргументах добавь последним параметром
путь JSON-файла. readFiles — точки входа, files — снимок зависимостей, не команда
читать все файлы в контекст модели. Контекст представлен каталогом topics: читай
нужные задаче темы; все темы выбранного уровня защищены снимком. Противоречия между
уровнями не разрешаются перекрытием: покажи источники и уточни решение.

В live загрузчик возвращает connections: id, configFile, adapterFile, mcpServer,
settings для каждого сетевого шага. При ready=false missing объясняет, что нужно
настроить. Выбор записи и адаптера делает код. Конкретные id и адаптер не фиксируются
в общем процессе. Доступность MCP-инструментов проверяется отдельно по адаптеру.
Start также возвращает entities и connections. Local/demo не требуют подключений.

Сетевой запрос может объявить внутреннее требование configFields в своей шапке:

```yaml
---
configFields: [issueUrlTemplate, projects]
---
```

Слот taskStore/codeStore определяется контрактом вызываемого экшена. Загрузчик всегда
проверяет baseUrl, adapter, mcpServer и дополнительные configFields выбранного запроса.
Это часть устройства запроса, не список внешних сущностей в requires.

Master-конфиг execution читается механизмом запуска всегда; requires.config задаёт
уровни данных для подключений. Отсутствующий необязательный team/my не заменяется
EXAMPLE.json. Недоступная выбранная запись означает ошибку настройки.

Для отчёта с обязательными фактами предпочтителен rendererFile внутри renderers/:
render(data, params) использует точные JSON-пути, validate(text, data, params) отвергает
потерю и подмену фактов. Compose-report вызывает этот модуль по явному аргументу.
Run next/execute даёт штатный путь выполнения; не создавай собственный шаблонизатор.


## Когда нужен renderers/

Добавляй эту папку, если результат должен точно переносить вычисленные данные в текст:
счётчики, суммы, периоды, списки записей. Для свободного редактирования текста достаточно
рецепта экшена и Markdown-шаблона.

Модуль экспортирует синхронные функции `render(data, params)` и
`validate(text, data, params)`. Первая возвращает готовую строку, вторая выбрасывает
ошибку при нарушении содержания. Обе работают без сети и записи файлов. Шаг
compose-report передаёт путь модуля в `rendererFile`; исполнитель формирует текст
через `run execute`, а `save` проверяет его независимо от способа получения.

Действующий пример: `processes/sdd-stories-report/renderers/`. Копируй его только
при сходном требовании к точности; поля SDD замени контрактом своего процесса.

## Допуск версии

После создания вызови definition validate с {process, params} (для demo также mode=demo).
Затем создай безопасные local/demo-прогоны с definitionTest=true. Для всех развилок
нужны завершённые прогоны каждой цели; отрицательные проверки структуры делаются
в отдельной временной копии. Передай {process, outputs:[имена папок]} в definition test,
затем {process} в definition publish. Все вызовы — через node tools/kit.js и spec.json.
publication.json создаёт код; ручное редактирование статусов и хешей запрещено.
При изменении защищённых ресурсов допуск становится draft. Status определения
действует/устарел от этого не меняется. Сквозная проверка в GigaCode указывается отдельно.
