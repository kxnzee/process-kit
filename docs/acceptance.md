# Приёмка в корпоративном контуре

Локальные тесты запускаются командой node tools/check-all.js. Следующие проверки требуют
настоящих GigaCode, секретов, прав и исходного Git-репозитория. Пока они не проведены,
не объявлять систему полностью принятой. Результаты сохранять с датой, клиентом/версией,
коммитом и дословным свидетельством; без значений токенов и сырых персональных данных.
Сценарии делать в отдельных свежих копиях, не в рабочей папке человека.

## Сценарии

## Материалы результата

- Все пункты исходной таблицы A1–H12 из final-check-prompt.md: статус и доказательство;
  A2, H5 и схема источников сопоставляются с актуальным structure.md/outputs.md, а не старой копией.
- Полные реплики С1 и С5, дерево outputs С1/С6, git status до и после, список точных коммитов.
- На сервере: ограничения master/team-*, владельцы ревью, отсутствие прямого/force push
  и удаления, стабильный тег на master. Проверить исходную историю settings на секреты
  отдельно в контролируемом контуре; не публиковать найденные значения.
- Повторить установку/секреты/хук на CLI, VS Code, настольном GigaCode и Windows.
- Если отдельный контекст шагов недоступен в клиенте, отметить фактическое ограничение;
  не принимать обещание изоляции по тексту инструкции.
- Бизнес-владелец подтверждает окно SDD, статусы, КЭ, определение принятого PR и
  полноту отрицательных доказательств. Локальная фикстура не доказывает живой отбор.

Отдельная производственная приёмка пилота: 3–5 реальных процессов, 5–10 участников,
4 недели, от 3 прогонов на человека в неделю, не менее 80% успешных прогонов и 200
накопленных запусков. Это исходные целевые критерии, не результаты этой проверки.

## Атомарные действия, SDD 1.1

- В demo fetch сохраняет только задачи, read-code — только свидетельства кода;
  assess независимо вычисляет report-data, compose отображает готовые показатели.
  Фактический report-data сверяется check-report.js --run с прежним эталоном fetch.json.
- При недоступном коде отрицательный SDD-вывод не появляется из пустого ответа:
  неопределённость сохраняется. Положительная метка остаётся достаточным признаком.
- Свидетельства с другим selectionId, чужими/повторными ключами или подменой labels
  блокируют расчёт. Source не заимствует итоговые группы из expected.
- Edit-text читает только переданный text, сохраняет его факты и не добавляет факты
  из report-data. Prepare-mail-draft сохраняет готовое тело без отправки/переписывания.
- Собственные процессы со старым run-query → report-data или send-mail требуют
  обновления маршрута/имени. Не подставлять старый или соседний экшен автоматически.

## Регрессии полноты данных и обязательных параметров

- Нет prsComplete или чтение неполное: без положительной метки/PR история остаётся
  непроверенной, а не «без SDD». Пустой prs подтверждает отсутствие только при true.
- Повторные ключи и пересечения stories/excluded/unverified останавливают расчёт.
- Отсутствующий query/template/rule блокирует preflight; явный корректный параметр
  прогона разрешает проверку без поиска похожего файла.
- Пустой modules отключает только фильтр КЭ; остальные условия отбора продолжают
  действовать. Нет modules или запись заполнена частично — ошибка настройки.

## Проверки после слабых агентных прогонов

- Новая команда из sources.template проходит общую проверку с предупреждениями TODO;
  live выбранного процесса остаётся заблокирован до заполнения его подключений.
- Изменение/удаление унаследованных общих или командных файлов в my блокируется;
  собственные my-файлы и согласованная настройка config/sources.json разрешены.
- Личный или командный запрос с собственным именем и совпадающей фикстурой проходит
  демо; чужая фикстура отклоняется.
- Папка demo имеет обязательный префикс проба-. Ошибка имени содержит подсказку.
- Новый командный/личный процесс переиспользует общий экшен по ссылке; новый владелец
  процесса сам по себе не требует копии действия.
