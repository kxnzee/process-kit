# Действие: составить текст по шаблону

Один шаг процесса. Превращает артефакт предыдущего шага в тексты по шаблону:
словарь переменных задаёт, что можно выводить. Новых данных не добывает — пункт без
цитаты остаётся без цитаты, а не дополняется догадкой.

## Аргументы

- data — обязательный путь к JSON-входу; процесс передаёт сохранённые данные явно.
- templateFile — обязательный точный путь к шаблону владельца. Содержимое и поля задаются шаблоном, не именем вызывающего процесса.
- maxFindingsPerReport — необязательное положительное целое; ограничение представления, только если шаблон предусматривает сворачивание. Без значения ничего не отбрасывается.

- rendererFile — необязательный локальный модуль владельца процесса с render/validate. Если он задан, используйте `kit.js run execute`: текст формирует код и проверяет соответствие данным. Свою подстановку шаблона не пишите.

## Рецепт исполнения

Если rendererFile задан, run execute вызывает готовый модуль владельца; save проверяет
его validate даже при ручном content. Если rendererFile отсутствует, шаблон — образец
структуры для модели, не программа для исполнения. Составь текст
самостоятельно из переданного data, сохрани заголовки и колонки выбранного шаблона.
Не разрабатывай рендерер/парсер шаблонов ради рабочего отчёта. Each означает повторить
строку или блок для каждого объекта, if — показать подходящий раздел. HTML-комментарий
с подсказками и управляющие {{...}} в готовый файл не попадают. Пиши готовый Markdown
в content команды save; служебный скрипт сам сохранит его файлом.

1. Прочитай JSON по обязательному аргументу data и шаблон по обязательному templateFile. Оба пути задаёт вызывающий процесс явно. Шаблон входит в снимок зависимостей; имя отчёта и предметная область не определяют путь автоматически.
2. Входные данные уже проверены своим производителем. Используй поля и правила представления из переданного шаблона; не навязывай схему конкретного процесса. Недостающие обязательные для шаблона сведения — ошибка входа, необязательные отмечай как непроверенные.
3. Счётчики и проценты брать из проверенного данных входного файла без пересчёта.
   Несогласованные показатели — ошибка входа, вернуть на шаг расчёта; шаблон
   задаёт только представление и не определяет бизнес-формулу.
4. Пустой раздел рендерить словами «нет записей», заголовки разделов не удалять.
5. Гранулярность задаёт шаблон: общий отчёт на всю выборку или отдельный текст на каждый
   объект. То, что объекту своё (пункты, цитаты, правила), рендерить в его блок, а не
   размазывать по общему тексту.
6. Число пунктов сверх `maxFindingsPerReport` сворачивать по правилу шаблона
   («и ещё N по правилу `<ruleId>`»), а не отбрасывать молча.
7. Мета-поля и пометки включай только по требованиям переданного шаблона и фактическим данным. Не требуй полей конкретного отчёта. Для демонстрационных данных сохраняй явную пометку demo.
8. Вернуть `report-text`.

## Что в этом действии НЕ делается

- не обращается к хранилищам и MCP-серверам даже для «быстрой проверки» — сеть у
  этого класса действий запрещена;
- не меняет вёрстку шаблона: не устраивает вид — человек кладёт свой шаблон в
  папку вызывающего процесса соответствующего уровня,
  а общий шаблон меняется только через PR.
