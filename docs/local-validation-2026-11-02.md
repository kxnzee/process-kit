## Что осталось решить или проверить

- Выполнить С1–С7 в реальном GigaCode на отдельных свежих клонах в корпоративном контуре.
  Сохранить полные реплики С1/С5, дерево outputs С1/С6, статусы git и отчёты ошибок.
  Здесь такие реплики и результаты не создавались искусственно.
- Проверить исходные теги, историю секретов и серверные ограничения Bitbucket по исходному репозиторию.
- Подтвердить более новые решения: шесть скиллов; team-<команда>-префиксы; taskStores/codeStores;
  полный след последнего шага в .run и второй файл для человека. Они явно описаны текущими эталонами.
- pre-push проверяет флаги из аргументов, но настоящий git передаёт хуку только имя remote и URL.
  Его прямые тесты флагов не доказывают блокировку force push. Перезапись истории должна запрещаться сервером.
- Условие защиты my в хуке проверяет одновременно локальное и удалённое имя my: переименование
  назначения через my:другая-ветка этим условием не закрыто. Политику защиты содержимого личной ветки
  и отправки в свой remote нужно уточнить перед расширением правил.
- check-prepush.js проверяет исходник хука, а не установленный .git/hooks/pre-push.
  Инструкция установки при уже имеющемся хуке не задаёт однозначно объединение двух проверок
  и не указывает chmod; README для простой установки chmod содержит.
- check-report.js ожидает report-data.json/report-text.md рядом в --run, тогда как исполнитель
  требует NN-имена файлов шагов. Нужен согласованный контракт имён или явные параметры артефактов.
- check-report сравнивает основные группы и числа; полная проверка причин excluded и всех полей
  не реализована. Самопроверки валидатора не равны полному покрытию требований.
- Лимит имени 1–4 слова не соблюдается программно; validate проверяет длину, paths.js — только шаблон.
- В validate.js остаётся резервный поиск ROOT вне paths.js.
- В документах очистка и миграция — инструкции модели; отдельные скрипты не найдены.
- Нет version и area у sdd-stories-report: валидатор считает их предупреждениями будущего пункта 4.
