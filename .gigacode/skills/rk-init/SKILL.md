# Состояние → одна процедура → возврат

Вход из поручения или потребности выбранной операции: исходная задача, personal-only/live, выбранный процесс при наличии,
ответы и согласия. Возврат: personalReady, отдельно connectionsReady только для
проверенного доступа, localServers (не нужны/установлены/отказ/ожидают подтверждения),
изменения, препятствие и ближайший шаг.

Это данные для продолжения работы, не форма ответа пользователю. Объясняй, что уже
настроено, что ещё нужно для его задачи и какой выбор требуется. Названия полей,
JSON и внутренние статусы показывай только когда они нужны человеку по GIGACODE.md.
Первый ответ адресуй самому человеку: коротко объясни ближайший шаг и задай только
недостающий вопрос. Например: «Можно начать без рабочих систем. Где хранить личные
настройки: только на этом компьютере или в вашем репозитории?» — если это ещё неизвестно.
Не оформляй ответ как рекомендации другому агенту («спросите пользователя…»).

1. До плана настройки и вопросов выполни `node tools/kit.js setup-status`.
   Это безопасное локальное чтение фактов, без сети, записи и сырых ошибок.
   Не подменяй результат памятью или чтением повреждённого конфига в чат.
   Проверь также configuration.state и configuration.missing. Файл с TODO означает
   незавершённую настройку даже при personalReady=true. Это готовность личной копии,
   а не всех подключений. Уточняй только незаполненные поля нужной операции; используй
   подтверждённые факты окружения и known, не начинай анкету заново. Неизвестные значения
   не придумывай. Для незавершённой командной ветки продолжай её настройку в той же
   области владения; не создавай вторую команду или личную копию ради заполнения TODO.
2. Для создания или восстановления личной копии применяй [модель владения](../../../docs/ownership.md).
   Выбери одну процедуру по personal.state:

   | Состояние | Следующее действие |
   |---|---|
   | ready | Сохранить известные выборы; настраивать только нужные подключения |
   | missing | Для новой копии читать references/create-personal.md |
   | invalid, incomplete, outside-personal | Читать references/repair-personal.md; не пересоздавать копию |
   | unknown или команда не дала результата | Объяснить препятствие, остановить настройку |

3. Для ready при вопросе о требованиях без записи: кратко сообщи, что уже готово,
   назови нужные источники по выбранному процессу без анкеты полей. Верни nextQuestion
   только о первом недостающем подключении: какая система и какой проект. Адрес,
   способ доступа и следующий источник уточняются после ответа, если они неизвестны.
   Не загружай инструкции новой установки и изменения подключений ради объяснения.
   known.team=without-team — сохранённое «без команды», не отсутствие ответа.
   Известные профиль, команда и хранение не спрашиваются заново. Критерии отчёта
   не являются настройкой личной команды; заданные процессом правила не требуют подтверждения.
4. Для согласованного изменения подключений читай только references/connect-existing.md.
   Для сохранения пожелания нужна готовая личная копия и явное согласие: простую
   настройку запиши в config/my/config.json.preferences, развёрнутое правило — в
   context/my/<тема>/CONTEXT.md с областью и датой. Не дублируй; новый контекст применяется
   только по явной ссылке. При отсутствии личной копии верни необходимость personal-only.
   Просьбу «называй меня…» сохраняй в preferences.addressAs точной строкой, «без имени» —
   как null. Меняй только это предпочтение, сохраняя профиль, Git-подпись и остальные поля.
   Постоянное пожелание «давай на ты/вы» сохраняй как preferences.addressMode=informal/formal,
   «отвечай короче/подробнее» — preferences.responseDetail=brief/detailed; «по ситуации» — auto.
   Разовое «сейчас кратко» относится только к текущему ответу и не меняет конфиг.
   Пожелание стиля учитывай сразу и при невозможности сохранения. Не создавай личную
   копию только ради стиля без поручения на настройку.
5. После изменений перечитай setup-status; проверка и сохранение — references/save-settings.md.
   При personal-only не проверяй неизвестные будущие системы. Объявленные подключения
   не означают проверенный доступ. Сохрани факты и nextQuestion; агент продолжает
   исходную задачу после устранения препятствия, не начинает её заново. При повреждённой настройке ближайший шаг — проверка/восстановление
   конкретной проблемы, а не сбор всей анкеты подключений или получателей письма.
