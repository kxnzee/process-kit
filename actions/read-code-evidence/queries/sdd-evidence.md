# Запрос: свидетельства кода для SDD

Вход task-records уже содержит отобранные истории. Источник только codeStore.
Ключи нужны только из входа; не ищи новые задачи и не повторяй отбор в Jira.
watchPath, keyPattern, keyFields и branchesToScan — эффективные параметры/координаты
подключения процесса. Значения по умолчанию: watchPath=openspec/changes,
keyPattern=[A-Z][A-Z0-9]+-[0-9]+, keyFields=заголовок/описание PR; branchesToScan
берётся из codeStores[].acceptTargetBranches, не из даты слияния. Окно старта истории не ограничивает дату слияния PR.

## Как ищется «PR с артефактами»

Главное правило: **важно не то, к какому объекту привязан коммит, а то, что он включён в PR,
в который включена стори.** Ключ в сообщении коммита, имя ветки и название PR значения не
имеют — решает факт входа коммита в PR и упоминание стори в этом PR. Эвристик нет.

1. **Смерженные PR за окно.** `bitbucket_list_pull_requests` с `state = MERGED`, `order = NEWEST`,
   `at` по каждой ветке из `branchesToScan`, пагинация до исчерпания данных. Окно startDate/endDate относится к старту
   работы истории, а не к дате слияния PR: ранний выход по closedDate потеряет свидетельства SDD. Из заголовка и
   описания PR берутся ключи по `keyPattern` (`keyFields`). PR без ключей стори дальше не
   рассматриваются.
2. **Есть ли в PR артефакты.** Для каждого PR-кандидата — список файлов PR
   (`bitbucket_get_pull_request_diff` с `path = watchPath`). Изменения под `watchPath` есть →
   PR содержит коммиты с артефактами. Пустой ответ «No differences found» → артефактов нет.
   Дифф целиком не грузить: он усекается, фильтр по пути — нет.
3. **Сверка с историей коммитов.** Дополнительно (для колонки «коммит» и для контроля):
   `bitbucket_list_commits` с `path = watchPath` по базовым веткам и `bitbucket_get_commit_changes`
   по подозрительным коммитам. Результат — вспомогательное свидетельство, а не критерий:
   коммит, который не попал ни в один PR со стори, стори не засчитывает.
4. **Один PR на много ключей.** Все ключи, перечисленные в одном PR с артефактами, получают
   признак SDD — в релизных PR перечислен раздел stories.
5. **Связи `PartOf`, имя ветки, префикс названия PR** не используются.


## Выход

code-evidence содержит selectionId и records[]; по каждому ключу — запись key, prs,
prsComplete, commit (если подтверждён), reason (при неполноте). У PR сохранить
id/url/state и changedPaths. Пустой prs допустим как отрицательное свидетельство
только при полностью пройденной области поиска и явном prsComplete=true.
Отсутствующий prsComplete означает «не проверено». Неизвестные changedPaths не
заменять пустыми. Не рассчитывать via, группы или процент.
