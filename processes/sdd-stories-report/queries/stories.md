# Запрос: отобрать истории для проверки SDD

Источник только taskStore. Выход task-records, контракт processes/sdd-stories-report/reference.md.
Читать задачи с метками и полной историей статусов через адаптер выбранного taskStore.
Код/PR не читать. Группы SDD, проценты и отчёт не вычислять.

## Параметры

Аргументы периода, keField и statusesAccepted передаются в объекте parameters; остальные условия ниже принадлежат этому процессу.

Приоритет: аргументы вызова → `параметры` шага → `params` процесса → координаты подключений.

| Параметр | Значение | Что означает |
|---|---|---|
| `startDate` | `01.01.2026` | начало окна по дате перехода в работу, включительно |
| `endDate` | текущая дата прогона | конец окна, включительно |
| `issueType` | `Story` | тип задачи «стори» этой инстансы системы задач |
| `project` | из координат подключений: `taskStores[].projects` | проект системы задач |
| `keField` | `customfield_18300` | поле «КЭ» задачи: массив ссылок на критичные элементы |
| `inWorkFrom` | `To Do`, `Backlog`, `New` | статусы до работы; стори, которые в них сейчас, выпадают из проверки |
| `statusesWork` | `In Progress` | имя статуса «взято в работу», по которому ищется дата в истории |
| `statusesAccepted` | из аргумента `statusesAccepted`, строка через запятую | «тестирование и далее»; обязателен, пустое значение — остановка |

Адреса серверов, имена подключений, хранилища кода и базовые ветки из
`repositories[].defaultBranch` здесь не повторяются — они уже есть в `config/`,
и запрос берёт их оттуда.

## Правила отбора

Стори попадает в набор, только если подтверждены **все** пункты 1–4:

1. **КЭ в поле задачи.** Если taskStores[].modules — пустой массив [], фильтр по КЭ
   отключён: не добавлять пустое условие «КЭ in ()» и не исключать истории по КЭ.
   Отсутствующее поле modules или частично заполненный список — ошибка настройки,
   не команда отключить фильтр. Для непустого списка КЭ отбора берутся из подключения:
   `taskStores[].modules`, каждая запись — объект `{ name, code }`. `name` — название
   для человека: в запрос оно не уходит, в отчёт и в чат не выводится, потому что может
   содержать имя системы или команды. Из `code` вида `CI03296913` для поиска берётся
   **только цифровая часть без префикса `CI` и без ведущих нулей**: `CI03296913` → `3296913`.
   В поле `keField` задачи должна быть хотя бы одна из полученных цифр (`"КЭ" in (...)`).
   Проверять именно полем задачи, а не упоминанием кода в тексте: сравнение по значению
   работает только на числовой id, код `CI…` полем не находится. Стори без подходящей КЭ в
   набор не попадает и в отчёт не выводится. Запись без `name` или без `code`, либо `code`
   не вида `CI0…` — остановка: список поправляет владелец координат, а не прогон.
2. **Старт работы в окне.** Получить полную историю задачи (`get_issue` с
   `changelog=true`, все страницы). Среди событий `field = status`, где `to_string`
   равно `statusesWork`, выбрать самый ранний `created` за всю историю, независимо
   от порядка ответа API. Это inProgressAt — первый переход в работу. Повторные
   переходы после возврата или переоткрытия дату начала не меняют. Только затем
   проверить `startDate ≤ inProgressAt ≤ endDate` включительно по календарным датам
   в часовом поясе пользователя. Первый переход до окна означает excluded, даже если
   повторный попал в окно. Стори без перехода — в unverified[] с причиной
   «нет перехода в работу в истории»; при усечённой истории или недоказанном первом
   переходе — unverified[], а не выбор первого доступного события.
3. **Сейчас задача уже в работе.** Текущий `status` не входит в `inWorkFrom`. Стори, вернувшаяся в `To Do`, исключается по текущему статусу, даже если начало работы подтверждено.
4. **Статус «тестирование и далее».** Текущий `status` ∈ `statusesAccepted` из аргументов.
   Строку разделить по запятой, убрать пробелы по краям; пустое значение — остановка,
   а не полный пропуск условия.


## Результат чтения

Вернуть meta, records[], excluded[], unverified[]. У прошедших отбор историй сохранить
key, summary, url, status, inProgressAt, assignee/responsible, labels. Неизвестные
labels не заменять пустым списком. Не помещать prs, via или бизнес-счётчики.
В meta сохранить эффективные параметры и queryFile до save. SelectionId вычисляется
командой сохранения по окончательному объекту; после save объект не дополняется. Пагинация до конца; отсутствие
истории или поля — явное непроверенное, а не отрицательное свидетельство.
В demo взять из dataFile только раздел задач через queryFixture(fixture, queryFile); результат
классификации из фикстуры не заимствовать. Иной путь query в фикстуре — ошибка.
