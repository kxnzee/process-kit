# Подключить системы к существующей личной копии

Вход: проверенный результат setup-status с personal.state=ready и
personalReady=true, исходная задача, выбранный процесс/подключения при наличии,
ответы и согласия. Личная копия, профиль, команда и хранение уже настроены.
Эта операция не создаёт my и не меняет её основание, профиль, команду или хранение.

## Ближайший шаг для человека

Используй summary и known из результата: кратко сообщи, что личная копия уже готова,
а для настоящего отчёта осталось подключить источники. Не выдавай план новой установки.
Если человек просит только объяснить, что нужно, дай ближайший шаг без записи файлов.
Когда согласие на настройку подключений ещё не получено, покажи короткий план только
этой работы и спроси его. Уже полученное согласие повторно не спрашивай.

Уточни только источник следующего недостающего подключения и нужный проект/репозиторий.
Не заставляй человека сначала заполнять весь список требований. Настройку файлов и
проверки ведёт агент; человек предоставляет неизвестные сведения и добавляет секрет
в хранилище клиента, когда это действительно потребуется. Токен в чат не проси.
Выбор «без команды» из known.team не отменяй вопросом о вступлении в команду.
Если для самого отчёта неизвестен критерий КЭ, поясни отдельно, что это отбор данных,
а не повторная настройка команды или личной копии.

## Работа с подключениями

Прочитай config/team/README.md и node tools/kit.js config --json. Выбор определяется
переданными id/defaults: не выбирай первую запись и не угадывай систему по примеру.
Количество connections в setup-status означает объявленные записи, а не проверенный
доступ. При personal-only без поручения на подключения никаких систем не настраивай;
верни готовую личную копию агенту для продолжения исходной задачи.

Если процесс выбран, получи его необходимые подключения через
node tools/kit.js config --process <имя> с --params <JSON-файл> при явных аргументах.
Временный файл создай в системной временной папке через JSON.stringify/json.dump;
удали после вызова, включая ошибку. Нет выбранного процесса — не угадывай его по команде.
Не проверяй неизвестные подключения будущей задачи.

Меняй только согласованные собственные записи и defaults в config/my/config.json,
сохраняя профиль, teamId, storage и preferences. Командные записи наследуются:
не копируй их и не создавай свой id с тем же значением, чтобы скрыть ошибку команды.
Недостающие общие сведения передай владельцу с конкретным объяснением.
Перед записью проверь git status и полный diff; чужие изменения не присваивай,
не stash и не reset. Изменённый человеком конфиг требует согласования его diff.

Секреты добавляются только в клиенте. В проектных settings допустимы ссылки $secret:,
значений секретов там нет. Не меняй глобальные настройки Git и ~/.gigacode/.
MCP проверяется безопасным чтением только подтверждённого сервера. Не объявляй доступ
готовым по наличию записи. Различай отсутствие секрета, 401, 403 и таймаут; по 403
не советуй безусловно заменить токен. Неизвестный сервис уточни, а не угадывай.

При недоступном чтении не запускай рабочий процесс. Сохрани согласованные изменения
и незавершённый результат по .gigacode/skills/pp-ai-init/references/save-settings.md этой папки, если запись разрешена.
Перед ожиданием перезапуска сохрани personalReady=true и connectionsReady=false
с конкретным препятствием. После перезапуска проверяй только недостающее, не создавай
личную копию заново. При запросе «ничего не менять» ограничься объяснением.

Для проверки, сохранения и возврата результата используй .gigacode/skills/pp-ai-init/references/save-settings.md.
Не отправляй файлы и не запускай рабочую задачу: её продолжает агент с сохранённой целью.
