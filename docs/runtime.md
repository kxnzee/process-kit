# Состояние и результаты запуска

Технический контракт реализации. Инструкция агенту и spec всех операций находятся
в .gigacode/skills/pp-ai-run-process/SKILL.md и не требуют чтения этого документа.
Журнал tools/lib/runtime/run-journal.js сохраняет факты; он не вызывает MCP и не выбирает ветки.

## Владение файлами

| Код | Ответственность |
|---|---|
| tools/lib/runtime/run-journal.js | start, begin/save, enter/leave, finish/fail, состояние, события и итог |
| tools/lib/runtime/history.js | Атомарное обновление индекса истории по output |
| tools/lib/core/paths.js | Имена и расположение результатов |
| tools/lib/entities/entities.js | Точки входа сущностей, каталоги контекста и подключения |
| tools/lib/entities/process-dependencies.js | Состав файлов снимка |
| tools/lib/contracts/artifact-contract.js | Проверка результатов по контрактам экшенов |

## Каталог запуска

Один запуск — новая outputs/<YYYY-MM-DD>_<коротко>/ от корня Git. Дата — местный день
запуска, не период данных. Короткое имя: 1–4 слова строчными буквами/цифрами через
дефис, до 40 символов. При совпадении добавляется -2, -3 вне лимита слов.
Для demo используется префикс проба-. Каталог не переиспользуется новым запуском.

```text
outputs/<дата>_<задача>/
  итог.md
  <файл результата>.md
  .run/
    inputs/input.md
    01-<шаг>.json
    02-<шаг>.md
    state.json
    run.md
    trace.jsonl
```

Inputs/input.md создаётся только при inputText. Каждый завершённый шаг имеет один
служебный артефакт; номера едины для вложенных вызовов. Artifacts связывает логические
имена с физическими файлами непосредственно в .run/. Finish побайтно копирует последний
артефакт в корень каталога. Промежуточные результаты сохраняются в .run/.
Имена человеческого результата проверяются validResultName на переносимость Windows;
итог.md и префикс NN- зарезервированы. Проверка завершения запрещает pending и stack.

## Состояние .run/state.json

| Поле | Назначение |
|---|---|
| last_step / last_step_name | Глобальный номер и имя последнего завершённого шага |
| next_step | Следующий допустимый шаг; end — конец текущего маршрута |
| status | running, completed или failed |
| params | Эффективные параметры текущего процесса |
| updated | ISO-время последнего фактического изменения |
| artifacts | Имена доступных артефактов → пути файлов внутри .run |
| artifactHashes | Имена артефактов → контрольные суммы; защищают завершённые файлы |
| title | Название текущей задачи для итогового файла |
| identity | Идентичность запуска и хеши входных файлов, формируется start |
| pending | Незавершённая попытка шага или null; заполняется begin до выполнения |
| last_artifact | Имя последнего сохранённого артефакта |
| cursorProcess | Текущий процесс, включая вложенный |
| stack | Стек вызовов подпроцессов: возврат и контекст родителя |
| scopeParams | Контрольная копия params текущего процесса; обновляется при enter/leave |
| recordedArtifacts | Все сохранённые физические артефакты, включая завершённые вложенные вызовы |

Не заполняй хеши, временные метки и завершение задним числом. Завершённые файлы не перезаписываются.

## Строка .history/runs.jsonl

| Поле | Обязательность и значение |
|---|---|
| ts | Обязательно; время завершения |
| process | Обязательно; имя процесса |
| output | Обязательно; имя папки внутри outputs/, без полного пути |
| итог | Обязательно; краткий итог из итог.md |
| уровень | Необязательно; общий, командный, личный |
| режим | Необязательно; local, live или demo |
| outcome | Необязательно; success, failed, draft |


## Идентичность и целостность

| Поле identity | Значение |
|---|---|
| process / mode | Корневой процесс и local/live/demo |
| params | Эффективные параметры корня; today уже разрешён |
| overrides | Явные аргументы отдельно от defaults |
| extraFiles | Явно добавленные зависимости |
| hashAlgorithm | sha256 |
| files | Пути выбранных файлов → SHA256 байтов |

Алгоритм рабочего журнала — SHA256; ручные снимки с другим алгоритмом не поддерживаются.
Start снимает определения, внутренние ресурсы экшенов, выбранные ресурсы процесса,
темы объявленных уровней контекста, нужные конфиги/адаптеры и служебный код.
Внешний текст сначала копируется в inputs/input.md, затем включается в снимок.
Execution master читается в любом режиме. Конфиги подключений выбираются из объявленных
уровней; local/demo не требуют реальных систем. Секреты в параметры не включаются.

Перед операцией проверяются хеши исходных файлов, scopeParams, artifactHashes и
recordedArtifacts. Состав зависимостей собирается повторно: новый ресурс экшена или
новая тема контекста меняет снимок и требует нового запуска. При enter сохраняются
область родителя и продолжение; leave возвращает результат под псевдонимом вызова.
При отсутствии снимка, несовпадении или неизвестном стеке безопасное продолжение
не доказано. Внешний эффект подтверждается ответом системы, а не статусом state.

## События, итог и история

Begin фиксирует pending и step_started перед действием. Save проверяет контракт,
записывает артефакт, событие step_completed и атомарно обновляет состояние.
Повтор прерванного save допускает только то же содержимое. Run.md содержит краткий
след операций, trace.jsonl — события с фактическим временем. Чувствительные данные
не должны попадать в параметры, события и диагностические сообщения.

Итог.md создаётся при start и обновляется журналом. В нём — задача, дата, исход,
краткое выполненное, источник данных, сведения о внешних изменениях и конечный файл.
Summary позволяет передать фактическое описание выполненного. Объём и период отчёта
проверяются по его данным; журнал не вычисляет эти сведения вместо экшена.
Для demo итог помечает пробный прогон и тестовые данные; отчёт содержит ДАННЫЕ ДЕМО.

Finish/fail обновляют .history/runs.jsonl: одна актуальная строка на output, без
дублирования при повторном завершении. Outcome — success/failed/draft; draft не
означает отправку. Индекс не хранит разговоры, предпочтения или сырые ответы систем.
История — внутренний модуль, отдельного CLI нет. Журнал обновляет её сам при
finish/fail. При повреждении/блокировке индекс не затирается;
результат может уже существовать, ошибка сообщается отдельно. Locks не удаляются
автоматически чужим запуском.

## Другие результаты и обслуживание

Настройка сохраняет outputs/<дата>_настройка/что-сделано.md. Заявка сохраняет
outputs/<дата>_заявка-<что>/заявка.md. У них нет .run/; формы содержатся в создающих
их скиллах. Имя каталога само по себе не доказывает выполнение настройки или отправку.

Outputs/ и .history/ исключены из Git, переноса и requires. Очистка .run/ — отдельная
явная операция обслуживания; результаты и история не удаляются заодно. Неоднозначные
старые каталоги не объединяются и не переносятся по догадке. Предпочтения находятся
в config/my или context/my по своему назначению, отдельно от истории запусков.

## Контракты экшенов и локальный runtime

ACTION.md объявляет единственный produces и его contracts. Артефакт шага может иметь
другой псевдоним: проверка использует контракт исходного порта экшена. JSON проверяется
по схеме; текст должен быть непустым, содержательные факты проверяет исполнитель.

Необязательный runtime: runtime.js загружается из папки экшена. RequiresFiles задаёт
его статические зависимости. Обработчики: dependencies возвращает файлы снимка,
prepare подготавливает параметры до begin, normalize нормализует результат перед
проверкой, validate проверяет семантику после JSON-схемы. Контекст обработчика содержит
cwd, processName, actionName, meta, params, inputs, mode; для результата добавляется
value. Выбор обработчика не зависит от имени экшена.

Правила evaluate-data — доверенные локальные JS-модули с evaluate(inputs, parameters).
Они должны быть синхронными и без побочных эффектов; это контракт, не песочница.
Нельзя загружать код из внешних данных. Шаблоны оформления — инструкции модели,
не программа рендеринга. Критерии конкретного процесса остаются в его папке.
