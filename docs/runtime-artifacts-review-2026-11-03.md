# Уточнение рабочего исполнения и сохранения артефактов

Ветка codex/reviewed-before-v2. Основание — наблюдение обычного исполнения слабой
моделью: лишнее чтение эталона, рассогласованный период, отсутствие сокращения текста
и ручная запись журнала после выполнения. Пользовательские документы не заменены
отчётом; этот документ хранит результаты доработки отдельно.

## Изменения

- Указаны конкретные рабочие входы. В demo разрешена только выбранная fixture;
  fetch.json/report.md/expected не являются примерами формы. Форма — docs/templates.
- Добавлен reference/runtime-artifacts.md с последовательностью и JSON spec-примерами,
  таблицей происхождения полей. Параметры передаются файлом/через API, не JSON-строкой.
- Run-journal.js сохраняет start → begin → save → finish/fail: начальный снимок до шага,
  попытку до исполнения, результат/событие/состояние сразу после него, итог и историю.
  Это сохранение, не исполнитель: MCP, тексты и решения branch остаются агенту.
- Период demo фиксируется по meta.window исторической фикстуры. Явный конфликтующий
  период блокируется. Date папки означает день запуска, не период данных.
- Технический selectionId формируется при сохранении готовых task-records. Следующий
  источник читает именно сохранённый файл; evidenceFromFixture связывает демо-код
  с этим отбором. Агент не обслуживает хеш вручную после изменения метаданных.
- Edit-text имеет проверяемое условие «коротко»: результат короче с теми же фактами,
  либо честное сообщение о невозможности сокращения. Добавлен конкретный пример.
- Compose-report заполняется моделью по форме шаблона. Для рабочей задачи не надо
  писать собственный рендерер each/if. Служебные директивы не остаются в результате.
- Шаблоны состояния/выходов и исполнитель синхронизированы с четырьмя шагами SDD;
  готовый report-text имеет свой пример формы. Репозиторные тесты не входят в обычный запуск.

## Проверки разработки

Check-all: 164 сценария прошли, включая 20 проверок run-journal. Проверены начальное
состояние, pending, порядок, подмена входа/выхода, согласованность периода, запрещённые
эталоны, повтор finish без дублей, частичная фиксация без повторного исполнения,
история ошибки и автоматический selectionId готового отбора. Валидатор — 0 ошибок,
одно прежнее предупреждение о служебном имени ветки. Скиллы прошли quick_validate,
git diff --check без замечаний.

## Независимые слабые прогоны

1. Первая повторная пара задач: /private/tmp/gigacode-independent.
   Текст сокращён с 88 до 70 символов, дата/число/ключ/URL сохранены. События идут
   started/step_started/step_completed/finished; хеши проверены и совпадают.
   SDD также завершился, но агент сначала писал свой рендерер и допустил локальные
   ошибки. Неудачные прогоны сохранены как failed, не скрыты. Это послужило основанием
   отдельно уточнить model-written Markdown и убрать ручное обслуживание selectionId.
2. Финальный свежий SDD-прогон: /private/tmp/process-kit-sdd-demo-retry.
   Итог: outputs/2026-11-03_проба-отчёт-sdd/итог.md.
   Команды: /private/tmp/process-kit-sdd-demo-retry-commands.log.
   Четыре шага завершены, состояние completed, одна запись истории. Период в params
   и report-data — 01.01.2026—20.01.2026. Отчёт побайтно равен финальному артефакту,
   все хеши identity/artifacts совпали. Нераскрытых {{...}} нет. Тестовые команды не
   запускались, чтение эталонов не зафиксировано, источником была выбранная fixture.

Слабые агенты: gpt-6-luna, reasoning low, без истории родителя в первоначальном
задании. Журнал аудита shell-команд не идеален: часть bootstrap описана кратко,
некоторые записи started имеют отдельную запись завершения. Это ограничивает полноту
доказательства каждого прочитанного файла; не является гарантией будущего поведения
любой модели. Штатный trace самого процесса ведёт служебная команда.

Ни native GigaCode/MCP, ни поддержка отдельного контекста, ни полный PR-перенос этим
прогоном не подтверждены. Подпроцессы и неизвестный стек не продолжаются по одному
last_step. Внешние эффекты не исполняются скриптом сохранения. Финальная приёмка в
контуре остаётся за владельцем. Правки локальные, без коммита или отправки.
