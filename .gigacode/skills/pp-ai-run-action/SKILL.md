# Одиночное локальное действие

Вход от диспетчера: выбранное действие, фактические входы, ожидаемый результат и согласия.
Прочитай его ACTION.md. Если это source/act или одного действия недостаточно, верни
ограничение диспетчеру; не запускай цепочку и не меняй контракт самостоятельно.

1. Уточни только отсутствующие входы через возврат диспетчеру. Для локального transform
   личная настройка и внешние подключения не нужны.
2. Подготовь spec по контракту действия и вызови `node tools/kit.js action <spec.json>`.
   Временный JSON сохрани в системной временной папке и удали после вызова, включая ошибку.
   Для edit-text: action=edit-text, mode=local, inputText — исходный текст,
   params.режим — подтверждённый режим, например «коротко».
3. При needs-model прочитай рецепт, подготовь фактический результат и повтори вызов
   с теми же входами и полем value. Ошибку проверки верни, не подменяй успехом.
4. Верни диспетчеру проверенный результат для ответа в чате. Только по просьбе сохранить
   укажи resultFile в новой папке outputs/<дата>_<имя>/. Не создавай журнал процесса
   и не используй finish для одиночного действия. Старые результаты не перезаписывай.

Не вызывай соседние скиллы; дальнейший маршрут выбирает диспетчер.
