# Контракт результата прогона

Один запуск — одна новая папка outputs/<ГГГГ-ММ-ДД>_<коротко>/ от корня Git.
Дата календарная, <коротко> — 1–4 слова строчными буквами/цифрами через дефис, до 40
символов. Повтор: -2, -3 вне лимита слов. Имя проверяет tools/paths.js.
Для demo префикс «проба-» обязателен: <дата>_проба-<задача> (не demo-<задача>).
Валидатор определяет демо-формат итоговой фразы именно по этому префиксу.

Папка не переиспользуется для нового запуска. outputs/ содержит только папки.

```
outputs/2026-11-02_проба-отчёт-sdd/
  итог.md
  отчёт.md
  .run/
    01-fetch.json
    02-read-code.json
    03-assess.json
    04-compose.md
    state.json
    run.md
    trace.jsonl
    inputs/input.md              если есть вход пользователя
```

Все шаги, включая последний, имеют один служебный артефакт. Его логическое имя
не задаёт физическое: state.artifacts связывает имена с файлами. Последний шаг
записывает тот же полученный результат вторым файлом для человека; повторять внешний
вызов ради второй записи запрещено. Промежуточный отчёт перед необязательным письмом
остаётся в .run/. Если результатом нужен именно отчёт — завершить маршрут после compose.

```
{
  "last_step": 4,
  "last_step_name": "compose",
  "next_step": "end",
  "status": "completed",
  "params": {},
  "updated": "2026-11-02T15:30:00+03:00",
  "artifacts": {"task-records":"01-fetch.json", "code-evidence":"02-read-code.json", "report-data":"03-assess.json", "report-text":"04-compose.md"}
}
```

state обновляется после успешной записи артефакта, атомарно; нумерация единая для
подпроцессов. Пути artifacts — только файлы непосредственно в .run/, без ../.
Входы отдельно в .run/inputs/, не маскируются под результаты завершённых шагов.
Состояние не является доказательством внешнего эффекта: act сохраняет его ответ/id.

Для продолжения нужен исходный снимок `identity`: `process` (точное имя), `mode`,
`params` (эффективные значения после разрешения today) и `files` (пути всех выбранных
процессов, ACTION.md, данных, подключений, контекста и входов → хеши байтов).
В рабочем запуске state, identity, trace, итог и историю сохраняет tools/run-journal.js
(порядок: runtime-artifacts.md). Его identity.hashAlgorithm=sha256.
Для проверки прежних ручных снимков хеш файла можно получить `git hash-object --no-filters -- <путь>` без записи объекта
и без изменения индекса. Укажи `identity.hashAlgorithm: git-blob`, чтобы не сравнивать
его с SHA256-хешами плана переноса. Внешний вход сначала копируется в .run/inputs/,
затем хешируется. Секреты в identity не включаются.
После шага `artifactHashes` хранит хеш каждого записанного файла из artifacts тем же
алгоритмом. До повторного шага сверяются исходные файлы, параметры и артефакты.
Старое состояние без снимка, неизвестный стек подпроцессов или несовпадение хешей
не позволяют безопасное продолжение: новый прогон. Структурный валидатор сам по себе
не доказывает совпадение identity — исполнитель обязан провести сравнение.

итог.md пишется всегда после начала прогона, даже при ошибке:
- заголовок задачи, дата;
- «Чем закончилось: готово» либо «не получилось: <причина>»;
- что сделано, откуда данные, сколько записей, что отправлено и кому;
- список существующих файлов для человека, без .run/ и системных ошибок.
Для демо: «Чем закончилось: Пробный прогон, ничего не отправлено. …» и «тестовые данные».
Главный отчёт тоже содержит «ДАННЫЕ ДЕМО». Нет сетевых вызовов и внешних изменений.

run.md — сводка маршрута и ограничений. trace.jsonl — события вызовов, без токенов,
сырых ответов и текста личных сообщений; ts, step, status и ошибка без чувствительных данных.
.history/runs.jsonl — индекс завершённых запусков, одна запись на output:
```
{"ts":"2026-11-02T15:30:00+03:00","process":"sdd-stories-report","уровень":"общий","режим":"демо","output":"2026-11-02_проба-отчёт-sdd","итог":"готово"}
```
Поле итог повторяет значение «Чем закончилось» без названия поля. В демо включает
пометку пробного прогона. Память предпочтений — context/my-preferences.md после согласия,
не машинная история. Не записывать один запуск повторно при продолжении.
Индекс обновляется `node tools/history.js --record <временный-json-файл>`: один
актуальный итог на output, остальные строки сохраняются. Повторное завершение
обновляет тот же output, не дублирует его. Временная запись без токенов — в системной
временной папке, после вызова удалить. При блокировке/повреждении истории не удалять
lock и не затирать файл вручную: итог сохранить, ошибку индекса сообщить отдельно.

Настройка: <дата>_настройка/что-сделано.md. Заявки:
<дата>_заявка-команда-<код>/заявка.md или заявка-подключение-<система>/заявка.md.
У них нет .run/. Обновление/сборка/публикация не объявляются реализованными по одному имени папки.

Очистка — отдельная явная операция обслуживания: только .run/ старше срока
runs_keep_days (по умолчанию 30); не результаты и не история. Безопасная миграция старых
папок требует проверенного соответствия; неоднозначное остаётся на месте. Не удалять
и не объединять старое с новой папкой по догадке. Миграция не является условием задачи.

outputs/ и .history/ не входят в git, requires, перенос и сборку. Разрешён только
локальный доступ. Пути вычисляет tools/paths.js; shell bootstrap хука — единственное
исключение для поиска корня перед загрузкой Node. Чат всегда содержит полный путь.

## Использование примеров во время работы

Для итог.md, state.json и строки истории используй соответствующий пример из
docs/templates/README.md. Для промежуточного JSON — выбранный пример artifacts/.
Заполняй фактическими значениями, пересчитывай identity/selectionId и хеши; null и
вымышленные значения из заготовки не являются состоянием выполненного шага.
Служебные проверки контракта не означают запуск тестового набора. Check-report и
selftest нужны при разработке/диагностике, а не для обычного рабочего ответа.

Новый рабочий запуск использует start/begin/save/finish/fail вместо ручной сборки
этих служебных файлов. Примеры выше объясняют форму, не разрешают задним числом
создавать события выполнения. Эффективный период фиксируется до действий: дата
папки — день запуска, а период исторической demo-фикстуры может быть другим.
