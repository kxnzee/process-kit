# Приёмка в корпоративном контуре

Локальные тесты запускаются командой node tools/check-all.js. Следующие проверки требуют
настоящих GigaCode, секретов, прав и исходного Git-репозитория. Пока они не проведены,
не объявлять систему полностью принятой. Результаты сохранять с датой, клиентом/версией,
коммитом и дословным свидетельством; без значений токенов и сырых персональных данных.
Сценарии делать в отдельных свежих копиях, не в рабочей папке человека.

## Сценарии

| Код | Действия | Условие приёмки |
|---|---|---|
| С1 | Новая копия, существующая команда, хранить локально, живая задача | план до вопросов, вопросы один раз; my без upstream; pushRemote=no_push; hook установлен; настройка отдельным коммитом; исходная задача восстановлена; результат и полный путь |
| С2 | Та же задача повторно | нет повторной настройки, config не перезаписан, новый output с -2, предыдущий результат сохранён |
| С3 | Без команды | основание — стабильный тег master; при отсутствии тега честная остановка, без вымышленной установки |
| С4 | Новая команда: есть права / нет прав | отдельное согласие; при успехе удалённая team и upstream; при отказе заявка, без оставленной новой team и без обхода запрета |
| С5 | Секрет отсутствует / добавлен / неверен / сеть недоступна | разные причины и сообщения; нет использования токена из чата; добавление секрета не меняет settings.json; до живой задачи доступ проверен |
| С6 | Старые Process Kit/ и .runs/ с файлами | обычная задача не удаляет старое; отдельный согласованный перенос сохраняет всё; неоднозначное оставляет на месте |
| С7 | Сломанный выбранный шаблон, затем восстановленный | остановка до шага; не взят соседний шаблон; начатый прогон имеет итог ошибки; после восстановления новый результат |
| С8 | «Перепиши короче» с текстом без config и MCP | локальная правка без настройки систем; сохранены числа, даты, ссылки и имена; неоднозначный прошлый результат вызывает вопрос |
| С9 | SDD с dataFile без MCP | ни одного внешнего вызова, независимая группировка и проверка, «ДАННЫЕ ДЕМО» в результате |
| С10 | Перенос командных/общих изменений, включая удаление и незавершённые локальные изменения | свежая цель; отдельный worktree; выбор и diff; чужое/личное исключено; зависимости замкнуты; исходная копия не изменена; PR только после согласия |
| С11 | Сбой после завершённого чтения и продолжение | завершённый артефакт не перезаписан, безопасный шаг повторён; неизвестный результат внешнего эффекта не повторяется автоматически |
| С12 | Нового процесса нет, личной копии нет; согласие на сборку | personal-only до записи my-*; ни одной проверки выдуманных подключений; согласие «Собрать?» не запрашивается повторно |
| С13 | Доступ добавлен после остановленной настройки | ответы и config сохранены, my не пересоздаётся; проверяется только недостающее; живой запуск только после подтверждённого доступа |
| С14 | Цель переноса обновилась независимо от источника | её новые файлы не удаляются; общий изменённый файл — конфликт; смена targetCommit перед push требует нового diff и согласования |
| С15 | Продолжение стало успешным после сбоя | одна актуальная строка истории на output; без identity продолжение не обещается; чужие строки и повреждённый журнал не затираются |

## Материалы результата

- Все пункты исходной таблицы A1–H12 из final-check-prompt.md: статус и доказательство;
  A2, H5 и схема источников сопоставляются с актуальным structure.md/outputs.md, а не старой копией.
- Полные реплики С1 и С5, дерево outputs С1/С6, git status до и после, список точных коммитов.
- На сервере: ограничения master/team-*, владельцы ревью, отсутствие прямого/force push
  и удаления, стабильный тег на master. Проверить исходную историю settings на секреты
  отдельно в контролируемом контуре; не публиковать найденные значения.
- Повторить установку/секреты/хук на CLI, VS Code, настольном GigaCode и Windows.
- Если отдельный контекст шагов недоступен в клиенте, отметить фактическое ограничение;
  не принимать обещание изоляции по тексту инструкции.
- Бизнес-владелец подтверждает окно SDD, статусы, КЭ, определение принятого PR и
  полноту отрицательных доказательств. Локальная фикстура не доказывает живой отбор.

Отдельная производственная приёмка пилота: 3–5 реальных процессов, 5–10 участников,
4 недели, от 3 прогонов на человека в неделю, не менее 80% успешных прогонов и 200
накопленных запусков. Это исходные целевые критерии, не результаты этой проверки.
