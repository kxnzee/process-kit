# CLI, параметры и результат

Из корня репозитория: `node tools/kit.js run <операция> <spec.json>`.
Spec — JSON-файл с уникальным именем в системной временной папке. Создай его через
JSON.stringify/json.dump, без ручного экранирования shell; удали после вызова,
включая ошибку. Не передавай JSON-строку вместо пути. Сохрани возвращённый output.
Используй публичный CLI; прямые экспорты tools/lib предназначены доверенному хосту,
не агенту, выполняющему пользовательский Run.

| Операция | Поля spec | Когда выполнять |
|---|---|---|
| start | process, mode: local/live/demo; необязательные date (только по явному требованию), slug, title, inputText, params, explicitParams, files | Один раз до первого действия. |
| next | output | Получить проверенную карточку следующего шага без выполнения. |
| choose | output, step текущей развилки, target; decision для model/user, approval: {source: adapter, requestId, proof} для продолжения user | Зафиксировать разрешённую ветку; поддерживает цепочки развилок. Затем next. |
| recover | output | Завершить прерванную запись и получить следующую карточку без повтора внешнего действия. |
| retry | output, attemptId, effect: {source: adapter, requestId, proof} | VerifyEffect должен подтвердить not-applied; новый begin требует нового approval. |
| execute | output, step; attemptId для уже начатой попытки | Выполнить объявленную локальную функцию и сохранить результат. Не вызывает MCP и не выполняет act. |
| begin | output, step; для act approval: {source: adapter, requestId, proof} | Только текущий узел после choose. Результат содержит pending.params и attemptId. |
| save | output, step, attemptId, artifact, extension: json/md/txt, content, next; для act effect: {source: adapter, requestId, proof}, проверенный verifyEffect с applied | После действия: artifact и next ровно из шага, JSON content — объект, текст — строка. |
| enter | output, step | Для узла процесс:, step — узел родителя, не имя ребёнка. |
| leave | output | После end ребёнка; возвращает параметры и продолжение родителя. |
| finish | output, resultName; необязательный summary | После конца корневого маршрута без pending и без stack. |
| publish | output, artifact, name | После finish, только если рядом с главным результатом нужен ещё один артефакт прогона: отчёт при черновике письма. |
| fail | output, reason; для pending act effect: {source: adapter, requestId, proof} с verified not-applied | При остановке: безопасная причина без секретов. |
| diagnose | output | По процедуре pp-ai-diagnose после передачи точного output и безопасных фактов; не повторяет процесс. |

Start возвращает state.params, entities, connections, readFiles (точки входа),
files (снимок). InputText автоматически копируется в .run/inputs/input.md, а params.input
содержит путь копии. Не создавай этот файл вручную. Params/explicitParams — явные
аргументы выше литералов шага и defaults процесса, в том числе во вложенных вызовах.
Defaults Action применяются ниже параметров процесса и литералов шага; одинаковые
эффективные параметры используются в preflight, next, begin и save.
Явный период, противоречащий demo-фикстуре, блокирует запуск. Start разрешает today и
значения по умолчанию один раз; при продолжении используй сохранённые state.params.

Пример local start для учебного процесса; дату и текст замени фактическими:

```json
{"process":"example","mode":"local","slug":"подготовить-письмо","inputText":"Фактический текст пользователя","params":{"to":"Подтверждённый получатель","subject":"Подтверждённая тема"}}
```

Для demo выбери согласованный process и передай params.dataFile с точным путём
его fixture.json. Период берётся из fixture.result.meta.window; данные другого
процесса или готовые ответы тестов не использовать. Для live нужны доступные средства
чтения; для шагов с подключением также нужны connections и доступный MCP. Для act
требуется разрешение на конкретное внешнее изменение.

Пример пары begin/save для первого шага учебного процесса:

```json
{"output":"<возвращённый output>","step":"edit"}
```

```json
{"output":"<тот же output>","step":"edit","attemptId":"<pending.id из begin>","artifact":"report-text","extension":"md","content":"Фактический отредактированный текст","next":"draft"}
```

Далее begin для draft, save с artifact=mail-draft и next=end, затем finish:

```json
{"output":"<тот же output>","resultName":"письмо.md","summary":"Подготовлен черновик, отправки не было"}
```

Примеры показывают форму, не подтверждают выполнение. Не копируй их даты и значения.
На branch используйте decisionMode карточки. При code выбор проверяется branchRule
процесса; при model агент проверяет условия и передаёт непустой decision. Контроллер
проверяет разрешённость цели, но не доказывает правильность семантического суждения.
Для SDD передайте wantsMail=true при запросе письма; счётчик plainCount проверяет код.
Для подпроцесса выполняй enter → его begin/save → leave. End ребёнка не завершает
родителя. Псевдоним результата берётся из узла вызова; физические номера общие.

Finish побайтно копирует последний артефакт, создаёт итог и обновляет одну запись
истории. ResultName — только имя файла с расширением md/txt/json/html, не путь: без
символов `< > : " / \ | ? *`, управляющих символов и завершающих пробелов/точек.
Имена устройств Windows CON/PRN/AUX/NUL/COM1–COM9/LPT1–LPT9 с расширением тоже
запрещены; итог.md и имена с префиксом NN- зарезервированы.

При ошибке оформления до save исправь черновик в том же pending. Если запись save
прервалась, сначала вызови recover; если шаг всё ещё pending, повтори save с тем же
attemptId и content. Другой content физического результата блокируется. Не повторяй
внешнее действие ради записи файла. При ошибке истории сообщи её отдельно: результат
может уже быть сохранён. Не удаляй чужие locks и не переписывай состояние вручную.

Входы, параметры, хеши артефактов и состав зависимостей проверяются журналом перед
каждой операцией. Изменение исходных файлов или добавление ресурса/темы требует
нового запуска. SelectionId отбора вычисляется при save; следующий экшен читает
именно сохранённый артефакт, не пересобранную копию. Identity, trace, временные метки,
итог и .history/runs.jsonl формирует код; не дописывай их вручную.

## Режим и готовность

В demo источники читают только dataFile рядом с процессом, без MCP. При конфликте
явного периода с фикстурой start отклоняется. В local источники допустимы только по
контракту выбранного действия; отсутствие локального вычисления означает работу модели.
В live нужны объявленные requires.config и готовые connections. Перед сетевым действием
читай указанный адаптер, нужный запрос/контекст и проверь инструмент с возвращённым mcpServer.
Ограничения, пагинация и полнота — по адаптеру; отсутствие данных не доказывается ошибкой чтения.

Не запускай check/entities перед обычным start: они могут исполнять код определения.
Start сам возвращает entities, readFiles, connections и проверенные параметры. Глубокая
проверка/отладка относится к отдельному поручению разработки, а не обычному запуску.
