# Сохранить результат настройки

Этот раздел читается только после согласованных изменений выбранной ветки настройки.
Он не даёт согласия на изменение файлов или внешний вызов.

## Проверка, сохранение и возврат

node tools/kit.js check, затем --process <имя> только для выбранного live-процесса.
Personal-only не должен блокироваться сетевыми зависимостями будущей задачи.
Не запускай интеграционные самотесты в рабочей папке как доказательство доступа.
Коммит личной настройки — только config/my/config.json и явно согласованные личные
определения по [модели владения](../../../../docs/ownership.md); командный конфиг в него не включается;
никогда git add . / -A. Перед коммитом проверь чужое staged: используй коммит только
своих точных путей (`git commit --only -- <пути>`) после проверки полного diff.
Нет изменений — нет коммита. Новый процесс сюда не входит.
Создай outputs/<дата>_настройка/что-сделано.md без .run/. Старую папку не перезаписывай.
Отчёт в чат до 8 строк: команда, хранение, доступы, незаполненное и
«Отчёт о настройке: <полный путь>». После каждого шага короткая строка «Готово: …».
Верни агенту для продолжения исходной задачи статус готовности и исходную задачу; её выполнение — отдельная операция.
Если config сохранён, но доступ ещё отсутствует, status=blocked, personalReady=true;
никакой успешной проверки доступа не записывай. Новый отчёт не затирает предыдущий.

## Форма заявки

Если по описанному сценарию нужна заявка, создай outputs/<дата>_заявка-<что>/заявка.md
без .run/. Заполни только подтверждённые сведения:

```markdown
# Заявка на <команду или подключение системы>
Назначение: <для какого процесса и какие операции нужны>
Данные: <название, код и владельцы команды либо название системы>
Что нужно: <конкретное действие получателя>
От кого: <подтверждённое имя пользователя>
```

Не оставляй заполнители, не включай секреты и не отправляй заявку автоматически.

## Форма отчёта настройки

В что-сделано.md сохрани фактический результат, включая незавершённые шаги:

```markdown
# Настройка Process Kit, <дата>
1. Команда: <название или без команды>.
2. Хранение личной копии: <локально или подтверждённый репозиторий>.
3. Настройки: <что заполнено и что осталось>.
4. Доступ: <что реально проверено, чего не хватает>.
5. Проверка процессов: <какая проверка выполнена и результат>.
Что изменено на компьютере: <фактические изменения>.
Внешние изменения: <фактические изменения либо ничего не менялось>.
```

После сохранения снова выполни node tools/kit.js setup-status и верни его результат
агенту для продолжения исходной задачи. Отсутствие подключения не отменяет готовность личной копии.
