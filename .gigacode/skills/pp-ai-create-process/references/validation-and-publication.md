# Проверки и локальная публикация

Читай перед проверками, definition validate/test/publish и при препятствии допуску.

Для явно заказанного черновика выполни доступные структурные проверки и перечисли
непроверенное; недостающие рабочие параметры не превращай в обязательную анкету.
Следующий полный lifecycle относится к готовому определению.
Выполни node tools/kit.js check, затем preflight нового процесса:
node tools/kit.js check --process <имя> --params <JSON-файл аргументов>.
Выполни node tools/kit.js entities <имя> <local|demo|live> <JSON-файл аргументов>.
Проверь ready, entities, missing; при ready=false уточни настройки, не выбирай
адаптер самостоятельно. Для demo/live укажи соответствующий режим.
Для демо добавь --demo; он не доказывает готовность реальных подключений.
Для готового определения вызови node tools/kit.js definition validate <spec.json> с process, mode=local/demo
и params проверки. Проверь обычный маршрут и каждый исход развилок штатными
local/demo-прогонами с start.definitionTest=true, без внешних изменений:
start → next → begin/save или execute (enter/leave для подпроцессов) → finish.
Save передаёт attemptId из begin/next. Негативные изменения определений проверяй
в изолированной временной копии; рабочее определение не ломай ради проверки.
После завершения передай {process, outputs:[имена проверочных папок]} в
node tools/kit.js definition test <spec.json>, затем {process} в
node tools/kit.js definition publish <spec.json>. Это локальный допуск определения,
не коммит и не отправка. Для GigaCode отдельно укажи фактический результат
сквозного прогона; local/demo не доказывает интеграцию. Проверь конечный файл, сохранность промежуточных результатов и отказ
при недоступном входе. Используй вымышленные данные без сети, отправки и других
внешних изменений; не выдавай рукописный ответ экшена за проверку живого инструмента.
publication.json создаёт инструмент; не заполняй статусы и хеши вручную.
DefinitionTest не отключает trusted approvals: маршрут с Action kind=act требует
verifyApproval до begin и verifyEffect=applied для save, а защищённое продолжение
decision=user также требует доверенного канала. Обычный gigacode-run их не даёт.
Если такой маршрут нужен для покрытия, без интеграции можно получить validated,
но нельзя обещать tested/published. Безопасный end корневой user-развилки не покрывает
остальные ветки. Не используй tests/trusted-integration.js в рабочей копии и не меняй
kind, decision, покрытие или publication ради обхода. Объясни препятствие; создание
доверенной интеграции не входит в эту операцию.
После изменения определения или зависимостей проверь и опубликуй новую версию.
Исправляй только свои изменения. Чужие ошибки и непроверенные маршруты укажи явно;
семантику вымышленного набора должен подтвердить владелец.

Для безопасного просмотра, в том числе незавершённого определения, используй
`node tools/kit.js definition inspect <spec.json>` с `{ "process": "<имя>" }`.
При неизвестной ветке можно передать level и team, как в каталоге. Inspect не выполняет
код определения и не пишет файлы. Статические ссылки и текущие хеши свидетельства
не доказывают полноту зависимостей, готовность запуска или завершение поручения.
`definition status` выполняет глубокую проверку и может
загружать JS определения (включая branchRule). Для безопасного чтения его не применяй.
