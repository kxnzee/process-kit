# Один порядок выбора и продолжения

Вход от ментора: исходная задача, цель, ответы, проверенные факты, согласия и результат
предыдущего шага при наличии. Неизвестное остаётся неизвестным. Пакет хранится
в диалоге, а не в новом файле или журнале запросов.

## 1. Найти возможности

Прочитай только YAML-шапки `.gigacode/skills/*/SKILL.md`: name и description.
Используй фактический каталог открытой копии, не список из прежнего ответа.
Ментор и сам диспетчер не являются кандидатами исполнения. Полный текст читай только
для выбранного скилла; описание возможности не означает её выполнение.

Для чтения каталога без тел инструкций:

```text
node tools/kit.js skills
```

Команда возвращает только name, description и путь SKILL.md. Она одинаково читает
LF/CRLF и не требует Git Bash, awk или синтаксиса конкретной оболочки.

Скилл — инструкция операции. Субагент — исполнитель в отдельном контексте, который
может использовать эту инструкцию. Доступных субагентов и их возможности определяй
по реальным средствам клиента; наличие скилла не доказывает наличие субагента.

## 2. Выбрать ближайшую операцию

| Намерение | Операция |
|---|---|
| Жалоба, сбой, просьба объяснить результат | Разбор по фактам, без нового запуска и настройки |
| Приветствие, возможности, инструкция по работе | Знакомство full; каталог процессов читается из текущей копии |
| Настройка копии, подключение, сохранение согласованного пожелания | Настройка только недостающего |
| Создание процесса, действия или адаптера | Соответствующий конструктор, без настройки неизвестных будущих систем |
| Передача изменений | Перенос на указанный уровень; неясное назначение уточнить |
| Рабочий результат или вопрос о требованиях к нему | Подбор процесса по правилам ниже |

Выбери скилл по назначению из каталога. Если подходящего нет, верни конкретное
ограничение; не выдумывай модуль. При первом обычном обращении дай brief-знакомство
один раз за диалог, если человек не просил пропустить; затем продолжай задачу. Жалоба сразу идёт в разбор.
Результат выбора — путь конкретного SKILL.md и вход операции, а не ответ человеку.

Для рабочего результата прочитай только шапки processes/*/PROCESS.md: name, title,
description, examples и status. Исключи учебные, устаревшие и чужие процессы по GIGACODE.md.
Выбери по результату и источнику; равные варианты требуют одного уточнения. Затем
прочитай входы выбранного процесса. Его определённые критерии не спрашивай заново.

- Процесс найден: локальное выполнение/демо не требует настройки систем. Для живого
  результата передай настройщику точное имя процесса и нужные ему подключения.
  Вопрос «что нужно для отчёта» разрешает объяснение требований, а не запись или запуск.
- Процесса нет: проверь контракты действий. Если одного локального transform достаточно,
  выбери скилл одиночного действия. Иначе предложи создание процесса; уже полученное
  согласие не спрашивай повторно. Подключения будущего процесса не угадывай.
- Личная готовность для создания или сохранения проверяется настройщиком в режиме
  personal-only. Она не равна доступу к внешним системам.

## 3. Прочитать выбранный скилл и выполнить

Прочитай выбранный SKILL.md до выполнения операции, включая объяснение требований.
Не заменяй его поиском по всем инструкциям, настройкам и примерам. Диспетчер передаёт
исполнение по этому пути, а не выполняет процедуру по краткому описанию из каталога.

Одна короткая последовательная операция выполняется в текущем контексте по выбранному
скиллу. Отдельный субагент нужен при пользе от изоляции объёмного материала либо для
независимой работы. Используй его только если клиент поддерживает этот способ и
разрешает делегирование. Не создавай субагента на каждый переход. Если изоляция
обязательна, но недоступна, верни ограничение; иначе работай в текущем контексте.

Передай исполнителю только задачу операции, путь выбранного скилла, нужные факты,
пути входов, ограничения и согласия. Не копируй весь каталог и историю диалога.
Раздельные контексты не изолируют файлы: запись в общие пути выполняй последовательно.
Исполнитель не выбирает соседний скилл: возвращает результат диспетчеру. Вопросы
человеку и окончательное объяснение результата проходят через ментора.

Активный запуск целиком ведёт исполнитель через run next. Не выбирай скилл для
каждого шага и не восстанавливай маршрут процесса по своему решению. Контроллер
возвращает разрешённую операцию; диспетчер продолжает только сценарии приложения.

## 4. Обработать возврат

Сохрани результат операции: статус, проверенные факты, изменения, пути файлов,
недостающие сведения или препятствие. Если скилл использует свой формат возврата,
сохрани его поля, не объявляй успех по одному слову completed.

- Операция завершена: продолжи следующую часть исходной задачи в пределах согласия.
  Знакомство не означает готовность настройки; настройка — завершение отчёта;
  диагностика — исправление. Объяснение требований не разрешает запуск.
- Нужен ответ или новое согласие: верни ментору nextQuestion и причину. Это только
  ближайший недостающий ответ, а не перечень всех будущих полей настройки.
- Конструктор вернул needs-action: сохрани continuation, выбери конструктор действия;
  после успеха верни его результат и continuation конструктору процесса.
- Рабочий исполнитель остановился: передай факты и точный output диагностике. Если
  журнал не создан, сообщи это ограничение. Диагностика не запускает автоматический ремонт.
- blocked/cancelled/failed: верни препятствие и ближайший шаг. Без новых фактов не
  повторяй тот же переход. Повторный отказ диагностики не запускает диагностику заново.

Общие границы — GIGACODE.md. Диспетчер не подменяет инструкции выбранного скилла,
не меняет инструменты ради обычного запуска и не расширяет согласие при передаче.
