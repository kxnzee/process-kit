# Копирование примера экшена

Выбери имя каталога и область записи по [модели владения](../../docs/OWNERSHIP.md#имена-определений).
Скопируй всю папку `actions/example/` в выбранную `actions/<имя>/`. Затем:

1. Переименуй name в ACTION.md в точное имя новой папки.
2. Опиши свою операцию, параметры и единственный результат; обнови consumes, produces и contracts.
3. Измени rules/default.md и contracts/result.json под новую операцию. Обнови пример examples/result.json.
4. Удали ненужные файлы. queries/default.md — образец для source; локальный transform его не использует. templates/ добавляй только для оформления.
5. Проверь `node tools/kit.js check --only actions` и preflight процесса, который будет вызывать новый экшен.

Исходный example — локальный transform: превращает text в JSON без изменения строки. В вызывающем процессе явно укажи параметры text и rule=default. Это копируемая сущность, а не блок с незаполненными полями.

```text
example/
  ACTION.md
  README.md
  contracts/result.json
  rules/default.md
  queries/default.md
  examples/result.json
```

## Поля

| Поле | Обязательность и значение |
|---|---|
| `name` | Обязательно; совпадает с именем папки. |
| `description` | Обязательно; что делает операция. |
| `kind` | Обязательно: source — чтение системы, transform — локальная обработка, act — внешнее изменение с явным согласием. |
| `adapter` | Обязательно: none для transform; environment-tool для чтения страницы доступным инструментом среды; иначе существующее подключение для source/act. Выбор записи — через taskStore/codeStore. |
| `consumes.artifacts` | Обязательный список уникальных имён входных артефактов; [] допустим. |
| `consumes.params` | Обязательный список уникальных имён параметров; [] допустим. Каждый параметр опиши в разделе «Параметры»: тип, обязательность, значения и default. |
| `produces` | Обязательный словарь ровно с одним ключом — именем результата; значение — непустое описание. |
| `contracts` | Обязательно; тот же ключ, что produces; значение text либо contracts/<имя>.json. |
| `runtime` | Необязательно; runtime.js в папке экшена с программными проверками и объявлением зависимостей. |
| `requiresFiles` | Необязательный список дополнительных статических файлов; попадает в снимок. |
| `Параметры` | Смысл, тип, обязательность, допустимые значения и источник каждого параметра. |
| `Граница операции` | Что входит в одну операцию; чтение, бизнес-расчёт и оформление выполняют разные экшены. |
| `Рецепт исполнения` | Последовательность операции, обработка неполноты и ошибок, условия остановки. |
| `Ограничения` | Явно исключённые операции; экшен не вызывает другие экшены и процессы. |

## Файлы экшена

- queries/<имя>.md — общие материалы операции, если нужны; специфический запрос процесса передаётся через queryFile и хранится у процесса.
- rules/<имя>.md — правила расчёта; параметр rule выбирает точное имя.
- templates/<имя>.md — оформление результата; параметр template выбирает точное имя.
- contracts/<имя>.json — машинная схема выхода.
- examples/result.json или result.md — пример формы с вымышленными значениями.
- reference.md — пояснения предметного контракта, если ACTION.md недостаточно.

Для query/rule/template опиши назначение, входные параметры, операцию, выход и условия остановки. Не копируй туда маршрут процесса. Не выбирай соседний файл при отсутствии выбранного.

## JSON-контракт

Поддерживается только подмножество из tools/lib/contracts/value-contract.js:

| Свойство | Значение |
|---|---|
| type | object, array, string, number, integer, boolean, null |
| required | Список обязательных свойств объекта |
| properties | Словарь вложенных схем по именам свойств |
| additionalProperties | Boolean: разрешены ли неописанные свойства |
| items | Схема каждого элемента массива |
| minItems / minLength / minimum | Минимум элементов / длины непустого текста / числового значения |
| enum | Непустой список разрешённых значений |
| anyOf | Непустой список альтернативных схем |
| description | Текстовое пояснение |

Не используй другие ключи JSON Schema: валидатор отклонит их.

```json
{
  "type": "object",
  "required": [
    "records"
  ],
  "properties": {
    "records": {
      "type": "array",
      "items": {
        "type": "object",
        "required": [
          "key"
        ],
        "properties": {
          "key": {
            "type": "string",
            "minLength": 1
          }
        },
        "additionalProperties": true
      }
    }
  },
  "additionalProperties": false
}
```

Проверка: `node tools/kit.js check --only actions`. Пример не заменяет расчёт по текущим входам.

## Переход к чтению источника

Сначала проверь, подходит ли общий run-query. Он принимает queryFile (точный путь к запросу процесса), taskStore и parameters. Образец queries/default.md перенеси к вызывающему процессу, если запрос специфичен для него; не зашивай имя процесса в экшен. Новый source нужен только для иной операции или контракта. Локальный пример ACTION.md не реализует чтение сети.

## Проверки функции

Если нужна программная проверка аргументов или результата, добавь runtime.js и укажи runtime: runtime.js в шапке ACTION.md. Экспортируй только нужные обработчики: dependencies(context) возвращает пути ресурсов, prepare(context) проверяет аргументы до начала, normalize(context) нормализует результат перед сохранением, validate(context) отклоняет неверный результат. Дополнительные статические зависимости перечисли в requiresFiles. Контекст содержит cwd, processName, actionName, meta, params, inputs, mode; у normalize/validate есть value. Эти файлы попадают в снимок; имя экшена не выбирает проверки в движке.

Процесс может назвать возвращаемый артефакт своим псевдонимом. Его входы через параметры задаются явно ({артефакт}); доступность проверяется на всех путях маршрута. Критерии, расчёт и схемы отдельного процесса хранятся у него и передаются аргументами; пример — evaluate-data, а не специальный экшен на каждый процесс.


Обработчики `execute(context)` и `canExecute(context)` позволяют журналу выполнить
локальное вычисление через `run execute`. Они не заменяют сетевое чтение адаптером
и не выполняют внешние действия act. Выход проходит ту же проверку, что при save.
JSON проверяется по contracts исходного порта; псевдоним артефакта процесса контракт
не меняет. Для текста проверяй важные факты в validate, если они определены операцией.

Локальный transform можно вызвать без процесса через `node tools/kit.js action <spec.json>`.
Spec содержит action, mode=local, inputText или params, при необходимости inputs и context.
Первый вызов без value возвращает рецепт; агент выполняет его и передаёт фактический
value повторным вызовом. Необязательный resultFile сохраняет результат в новой папке
outputs/. Результат по умолчанию возвращается вызывающему агенту.
