# Передача работы между системными скиллами

Это внутренний контракт, не новый файл установки и не реплика человеку. Вызывающий
передаёт только нужные сведения, а не весь диалог и сырые ответы систем. Согласие
передаётся с областью действия: на сборку, изменение настроек, сохранение пожелания
или отправку конкретного diff. Одно согласие не заменяет другое.

## Общие сведения

- Исходная задача дословно; выбранный процесс и режим live/demo/local, если определены.
- Явные параметры и уже полученные ответы с происхождением; не считать догадку ответом.
- Текущая папка и подтверждённый уровень владения, команда/хранение, если определены.
- Какая работа разрешена и что уже сделано. Повторный вызов не начинает её сначала.

Результат любого скилла: status = completed / blocked / cancelled / failed,
что сделано, изменённые пути, оставшееся действие и причина, если не completed.
blocked — нужны данные/доступ/решение; cancelled — человек отказался; failed — ошибка
операции. Вызывающий не продолжает зависимую операцию после этих трёх исходов.
Результат процесса дополнительно содержит outcome: success / failed / draft.
status=completed не означает, что внешнее письмо отправлено: черновик — draft.

## По операциям

| Переход | Что передать | Что вернуть |
|---|---|---|
| mentor → init | причина настройки; режим personal-only или live; выбранные process/подключения, либо «ещё не определены»; известные ответы | personalReady, connectionsReady по запрошенным id, что сохранено и что требует перезапуска |
| mentor → create-process | согласие на сборку, личная готовая копия, исходная задача и известные параметры | process, новые/изменённые пути, что проверено, возможность запуска |
| mentor → run-process | process, режим, явные параметры, текст/путь входа, требуемые подключения | outcome, outputDir, summaryFile, фактические внешние изменения и ограничения |
| mentor → promote-* | назначение, уже выбранные материалы/ответы, область согласия | commit, targetCommit, pushed, prUrl либо pendingAction; путь отдельной рабочей копии |

personalReady не означает доступ к системам. Неизвестные зависимости будущего процесса
не проверяются заранее: сначала личная копия и сборка, затем целевая проверка live.
Из blocked не создаётся цикл init → mentor → init без новых сведений от человека.
Ожидание перезапуска клиента возвращает blocked, а не запускает повторную настройку.

Короткую запись результата держи в контексте вызывающего. На диск — только уже
предусмотренные отчёт настройки, состояние/итог прогона или отчёт подготовки переноса.
Не создавай новый дублирующий журнал разговоров и не записывай согласия с токенами.
