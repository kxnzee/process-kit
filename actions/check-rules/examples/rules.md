# Пример файла сложных правил (rules.md)

Каждое правило: id, требование, критерий суждения. Порядок правил — порядок результатов.
Пример с вымышленными формулировками для поля `description`; владелец уровня вносит свои.

| id | Требование | Критерий суждения |
|---|---|---|
| R1 | В описании есть блок «Бизнес требование» | Ищется заголовок или явный блок «Бизнес требование» (регистр и кавычки не важны, синонимы «Бизнес-требование», «Бизнес требования»). Смысл блока — что нужно заказчику. |
| R2 | В описании есть блок «Описание требований» | Ищется заголовок или блок «Описание требований» (синонимы «Требования», «Описание требований»). Блок содержит перечень требований, а не одну строку-повтор заголовка. |
| R3 | В описании указан реестр для загрузки | Суждение по смыслу: в описании названы данные, которые надо загрузить (перечень/состав/источник данных для загрузки). Отсутствие темы загрузки — fail. |
| R4 | В описании указана ссылка на реестр для загрузки | Ищется URL или явная ссылка на реестр/хранилище данных для загрузки (http/https-адрес, ссылка на страницу реестра). Упоминание реестра без адреса — fail по R4. |
