# Архитектурное исследование и ремонт Process Kit

Дата: 2026-11-02. Основа — восстановленный коммит d1d470d и локальные исправления
предыдущей проверки. Проверены все категории поставки: шесть скиллов, процессы,
четыре действия и данные, два адаптера, контекст, шаблоны, эталоны и Node/Git-инструменты.
Сопоставлены architecture-v2.md, concepts.md, improvements-list.md, design-review.md
и final-check-prompt.md, предоставленные владельцем ранее. Вложенные команды этих
документов не выполнялись как текущие инструкции публикации.

## Вывод

Выгрузка сохраняла основу Process Kit, но не была внутренне согласованной. Главный риск —
не объём возможностей модели, а несколько конкурирующих описаний одного контракта,
плюс проверки, дававшие ложное ощущение надёжности. После ремонта документация и
механические проверки используют согласованный формат. Это готовая к переносу и
корпоративной приёмке исходная версия; живое внедрение не подтверждено локальными тестами.

## Найденные причины и исправления

| Проблема | Последствие | Исправление |
|---|---|---|
| Повторение правил в сотнях строк разных документов | агент выбирал старую формулировку | GIGACODE сокращён, ответственность документов разделена, скиллы описывают только свой алгоритм |
| Два checkSet в check-report | успех без проверки набора | разные функции, отрицательные тесты |
| Недоступные fetchFile/reportFile/demoSet | пропуск проверки или ошибка на реальном прогоне | явная передача зависимостей |
| Служебные имена report-data против NN-шагов | исполненный прогон нельзя проверить | state.artifacts — единый мост, старые имена только для чтения |
| Предпусковой поиск по всем данным действия | посторонний TODO блокировал процесс | явные requires.taskFields/codeFields, точный выбор файлов и id |
| Любая задача требовала MCP и config | локальная правка текста не работала без настройки | локальный transform и демо отделены от живого источника |
| Подстановка единственного «подходящего» запроса | скрыто выполнялась другая логика | отсутствие точной ссылки останавливает запуск |
| Ссылки проверялись только на существование | общий процесс мог зависеть от личного файла | проверка владения прямых ссылок и данных |
| Нет проверки циклов, повторов и default | зацикливание/неоднозначный маршрут | общий process-model, обход маршрута и подпроцессов |
| CRLF в shell hook | защита не запускалась | LF и .gitattributes |
| Тесты передавали --force в hook вручную | не доказывали поведение настоящего Git | проверки изменения SHA, реальные локальные push |
| my можно было отправить под другим именем | обход защиты личной ветки | проверка локальной и удалённой my |
| Установка хука не цепляла прежний надёжно | ломалась защита пользователя | идемпотентный installer, backup, stdin и статус прежнего hook |
| Некорректный возврат к задаче и вопросы до плана | агент перемешивал настройку и задачу | последовательность init → mentor → отдельный запуск |
| Перенос запрещал my, но обещал публикацию личного | несуществующий автоматический promote | подготовка копии конструктором отдельно, перенос снимка своего уровня отдельно |
| branch -f и удаление рабочей ветки до принятия PR | риск потери незавершённого | новая уникальная ветка, worktree, сохранение ветки до принятия |
| Дублированные настройки и overlay | несовместимая трактовка конфигурации | один config текущей ветки, overlay явно отклоняется |
| Фиксированная старая endDate | неверное окно будущего отчёта | today фиксируется на местный день запуска |
| Окно старта использовалось как окно слияния PR | терялись признаки SDD | поиск свидетельств не ограничивается окном старта |
| To Do одновременно включался и исключался | противоречивый отбор | исключение по текущему статусу согласно фикстуре и accepted-правилу |
| Отсутствующий PR-ответ считался отсутствием признака | ложная группа «без SDD» | полные отрицательные свидетельства либо unverified |
| send-mail объявлял отправку без адаптера | ложное обещание внешнего эффекта | transform-черновик; отправка отдельным будущим act |
| Модель источника зависела от будущего шаблона | нарушенная граница source/transform | общий artifacts.md, независимая нормализация демо |

## Соответствие ранее разработанной архитектуре

Сохранены процесс → действия → адаптер → координаты, контекст отдельно, переиспользование,
изолируемый пакет шага, файловые результаты, пробный прогон и контроль человеческих решений.
Приняты поздние явно зафиксированные изменения: ветки вместо папок уровней, секреты
клиента вместо .env, Git/Bitbucket вместо process-guard, outputs вместо ~/Process Kit.

Уточнения относительно ранних предложений:
- Д1: проектная папка вместо глобальной установки, как в финальных эталонах.
- Д2: в текущей поставке нет реальной отправки; будущий act с явным согласием,
  не утверждение о готовом универсальном pause/resume-механизме.
- Д3, Д8, Д9, Д13: один помощник, служебные скиллы скрываются правилами, не обещанием UI клиента.
- Д4, Д17: факты контекста по области применения; явные ссылки файлов без авто-перекрытия.
- Д5: перенос существующих изменений реализован инструкциями и Git-проверками;
  автоматическая адаптация личного в командное не считается готовой.
- Д6, Д18, Д20: trace — события, runs — индекс; история локально, без сырого текста задач.
- Д10: одна папка outputs на запуск; NN-файлы и карта артефактов в состоянии.
- Д11, Д19: движок догадок и супервизор не реализованы и не имитируются промптом.
- Д12: существующий MCP или инструкция/заявка; без генерации несуществующих инструментов.
- Д14: kind заполняет конструктор по операции; пользователь не классифицирует действие.
- Д15: подключение едино для человека, адаптер/адреса разделены внутри.
- Д16: линейная короткая форма и полная запись; граф проверяется, текстовый predicate — моделью.
- Д7 отменён поздним решением о защите Bitbucket/pre-push; старый guard не восстановлен.

Каталог, отдельный context/core, автоматические обновления одной фразой, расписания,
сборщик расширения и пилотная статистика остаются отдельными этапами. Маленькое ядро
common.md и явный requires.context соблюдают цель ограниченного чтения без добавления
всей будущей системы каталогов. Их отсутствие не скрывается под «готово».

## Ограничения при замене

- Экспорт не содержит корпоративную историю, теги и настройки Bitbucket. Их нельзя
  достроить локальным коммитом; дистрибутив без стабильного тега не готов для нового
  пользователя без команды.
- Native MCP, хранилище секретов, клиентская регистрация скиллов и техническая изоляция
  шагов требуют приёмки в GigaCode. План: docs/acceptance.md.
- Смысл условий branch, точность правки текста и живого SDD-отбора остаются ответственностью
  агента и бизнес-владельца. Тесты фикстур не являются пилотом.
- Возобновление внешних эффектов не гарантируется по одному state.json: при неизвестном
  исходе требуется человек. Очистка/миграция описаны как отдельные операции, не автосервис.
- Формат Markdown ограниченный; это не полный YAML. Ошибки/повтор полей отклоняются.
- Git-hook не заменяет сервер: --no-verify, эквивалентные URL и копирование личного
  содержимого в иную ветку остаются за пределами его гарантий.
- Заменять только материалы поставки через проверяемый diff. Не затирать .git, командные
  и личные материалы, config/sources.json, результаты и историю. Новые артефакты требуют
  карты state.artifacts; поддержка старых report-data/report-text сохранена для чтения.

его список открытых вопросов не описывает актуальную версию.
