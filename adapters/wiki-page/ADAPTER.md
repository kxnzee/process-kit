# Адаптер: страница вики (kind = `wiki-page`)

Как читать страницу сценария, регламента или методики из системы документов этого типа.
Здесь только механика обращения к системе: что сверять, какие значения процесса с чем
сопоставлять и что с расхождением делать — у вызывающего действия и процесса.

Исторические наблюдения ниже не заменяют проверку схемы объявленных инструментов в текущей
сессии. Не конструируй неподдерживаемые параметры по одному примеру.

## Подключение

MCP-сервер: выбирается по домену адреса страницы из объявленных в сессии; этот файл намеренно
не содержит имён серверов конкретной машины — имя фактически выбранного сервера попадает в
артефакт сверки (`source.connection`), и по нему результат воспроизводят.

Адрес страницы задаёт вызывающий процесс своим параметром (`methodologyUrl`): идентификатор
берётся из адреса, адрес в текстах артефакта не выдумывается. Сервер чтения выбирается по
**домену этого адреса**, а не по порядку серверов в сессии: у копий бывает два контура, и
подстановка «доступного вместо нужного» даёт правдоподобную сверку по чужой странице.
Домен не совпал ни с одним объявленным сервером — остановка и вопрос человеку.

Имена инструментов строятся от выбранного сервера: `mcp__<сервер>__<имя>`. Как именно в этой
копии объявлен сервер чтения страницы, записывает вызывающая копия — в своей папке адаптера
или в своих настройках; этот файл имён машины не содержит. Имя фактически выбранного сервера
попадает в `source.connection` артефакта сверки, чтобы результат можно было воспроизвести.

Инструментов нет в списке сессии — сначала загрузить их `tool_search` с запросом
`select:mcp__<сервер>__<инструмент>`. Если и после загрузки их нет, сервер в сессии не поднят:
остановить работу и сказать человеку (лечится перезапуском подключения), не восстанавливать
содержимое методики по памяти и не читать её из прошлых прогонов.

Секретов в адаптере нет; настройки клиента содержат ссылки вида `$secret:<имя>/<ключ>`.

## Операции

Все операции — чтение (`read`). Операции записи здесь нет: маршруту, который выбрал этот
адаптер, публикация не нужна. Копии, которой нужно создавать или обновлять страницы, нужен
свой вариант описания с операцией записи класса `act` и явным согласием человека.

| Capability | Что нужно на входе | Что возвращается | Зачем |
|---|---|---|---|
| `readPage` | идентификатор страницы (число из адреса), запрос тела и атрибутов страницы | текст страницы, номер версии, дата и автор последней правки, ключ и название пространства, заголовок | тело методики и атрибуты, без которых непонятно, на чём сверка |
| `readPageHistory` | идентификатор страницы | автор, дата и номер последней правки | страница правится вручную: без этого непонятно, актуальна ли сверка |
| `readVersion` | идентификатор страницы и номер версии (целое число) | тело указанной версии | содержание правки видно только сравнением тел: отдельной таблицы «что изменилось» у страниц обычно нет |
| `listChildren` | идентификатор родительской страницы | перечень дочерних страниц: идентификатор, заголовок, статус | найти связанную страницу, когда её адрес не известен заранее |
| `findByTitle` | пространство и заголовок (или его часть), смещение и размер порции | найденные страницы с версиями и ссылками | поиск, когда перечня дочерних страниц не хватает |

Точные имена инструментов и параметры берутся из схем, объявленных в сессии, — таблица
описывает смысл операции, а не имена вызовов. Имена возможностей — имена операций адаптера.

## Полнота и отказы

- Текст страницы читается **до последней порции**: если ответ сообщает о продолжении или
  усечении, чтение повторяется. Недочитанное не считается сопоставленным: у шага для этого
  `readToEnd: false` и список несопоставленных разделов с причинами.
- Перечень дочерних страниц сервер отдаёт порцией (часто не больше 25) и без смещений. Если
  пришло ровно максимум порции, полнота перечня не доказана: нужен `findByTitle` с пагинацией.
- `findByTitle` фильтрует заголовок как подстроку: совпадением считается точное равенство
  заголовка после нормализации (регистр, падеж, «ё»), остальные строки отбрасываются с пометкой.
- Успешный пустой ответ означает «страниц нет». Отказ доступа (401 — авторизация не принята,
  403 — отказ в доступе) и таймаут — разные исходы с разными причинами: при таймауте адрес не
  меняется и чтение вслепую не повторяется, при 403 замена токена ничего не гарантирует.
- Пространство и прочие атрибуты берутся из ответа `readPage`, а не выдумываются по образцу
  других страниц.

## Пробный прогон

В демо этот адаптер не используется вовсе: процесс читает демоданные из фикстуры, а сверка со
страницей в демо-прогоне выключена параметром, потому что сеть запрещена режимом. Демо поэтому
ничего не говорит о доступе к странице.

Для живой проверки достаточно одного безопасного чтения: `readPage` по адресу из
`methodologyUrl` с атрибутами страницы (версия, пространство, автор правки) — без тела, если
нужно только подтвердить доступ. Успешный ответ с номером версии означает, что сервер выбран
по домену верно и страница читается; тело тогда дочитывается уже шагом сверки. Пустой ответ,
отказ доступа и таймаут — три разных результата: первый означает «страницы там нет», второй —
вопрос к правам, третий — недоступность, а не отсутствие доступа.
