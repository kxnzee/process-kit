# Термины Process Kit

Общие для всех уровней пояснения к словам, которые встречаются в процессах и отчётах.
Файлы этого уровня не содержат ничьих конкретных адресов: ни проектов, ни досок, ни
адресов входа, ни имён людей — они живут в настройках команды и в файлах командного и
личного уровня.

| Термин | Значение |
|---|---|
| Процесс | маршрут из шагов, файл `processes/<имя>.md`; шаг ссылается на действие по имени |
| Действие | атомарный шаг `actions/<имя>/ACTION.md`; класса `source` (читает систему), `transform` (считает без сети), `act` (внешний эффект после «да») |
| Адаптер | файл `adapters/<система>.md`: какие инструменты MCP, как пагинировать, где ограничения |
| Конфиг | `config/sources.json`: записи `taskStores` (система задач) и `codeStores` (репозитории) — id, адаптер, `mcpServer`, проекты и репозитории, ограничения; `defaults` — что брать по умолчанию. Рабочего файла в общем уровне нет, только шаблон |
| Артефакт | результат шага, файл в папке запуска `outputs/<имя>/.run/`; следующий шаг получает путь к нему. Последний шаг пишет свой файл туда же и второй файл — в `outputs/<имя>/` для человека; из `.run/` ничего не копируется и не переименовывается |
| Демо-прогон | прогон с `dataFile=`, где выборка берётся из фикстуры; артефакты помечены «ДАННЫЕ ДЕМО» |
| Не проверено | условие отбора не подтвердилось ответом системы — это не то же самое, что «не найдено» |
| Уровень | ветка: `master` и `master-<имя>` — общий, `team-<команда>` и рабочая ветка, ответвлённая от неё, — командный, `my` — личный |

## Общие правила для отчётов

- Числа и проценты считаются по правилам шаблона, а не «на глаз»; если часть выборки не
  проверена, вместо процента пишется «не проверено».
- Ссылка на задачу или PR выводится ключом: ключ — текстом, адрес — за ним, ссылкой.
  Длинный адрес открытым текстом в таблицу не вставляется — он ломает выравнивание.
- Пустой раздел пишется словами «нет записей»; заголовки разделов не удаляются.
