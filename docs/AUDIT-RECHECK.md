## Что изменилось после повторного воспроизведения

EPERM не считается конкуренцией сам по себе. Проверяется операция link, её исходный
lock-путь и повторный stat: только исчезнувший или заменённый файл позволяет одну
атомарную попытку захвата. Если новый владелец уже занял путь, он сохраняется; если
файл прежний, отказ доступа остаётся неизвестным владельцем. Повторов по таймеру,
подавления всех EPERM и ослабления contention-теста нет. Неизвестная ошибка сохраняет
безопасные факты stat для разбора. Детерминированный тест до исправления падал;
после исправления отдельно проходят released/replaced/unchanged и genuine-denial.

Повторное ревью остальных Findings обнаружило дополнительные обходы ARCH-001/002/007.
Для каждого до исправления получен негативный результат. Параметры entities теперь
проверяются до manifest; adapters участвуют в проверке владельца. Явные files и
requiresFiles должны иметь канонический путь и регистр корневого каталога: traversal,
обратные слеши и регистровые алиасы не скрывают владельца. Прямой Action CLI проверяет
сам Action и объявленные файлы до загрузки runtime; обычный literal text не превращается
в файловую ссылку, Process для одиночного Action не создаётся.

Пользовательский params.input больше не принимается за автоматически созданный вход.
Исключается только копия Controller в собственном output; признак передаётся внутренним
контекстом, не пользовательским JSON-флагом. Артефакты предыдущих шагов по-прежнему
проверяются журналом; неразрешённый токен не открывается как произвольный файл.

Публикация проверяется по эффективным параметрам до dependency hooks. Существующий
статический inventory учитывает rulesFile/rendererFile и соседние helper-файлы,
в том числе разные варианты одного child. Непокрытый JS не выполняется даже при
последующем ожидаемом отказе публикации. После настоящего validate → definitionTest →
test → publish допустимый override работает. Форматы определений и Run Journal
не менялись; новые Controller, runtime или журналы не добавлены.
