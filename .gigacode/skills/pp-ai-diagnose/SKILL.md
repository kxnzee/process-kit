# Разобрать запуск

## Вход и возврат

Вход: повод (сбой/жалоба/объяснение), исходная задача, ожидаемое и наблюдаемое,
точный output или сведения для его выбора, безопасная причина остановки и reportFile,
если файл уже создан. Неизвестное не выдумывай. Возврат: status=completed/blocked,
выбранный output при наличии, подтверждённые факты, предположения, ограничения,
reportFile при создании, следующий шаг и необходимость помощи разработчика.
Completed означает завершённый разбор, а не исправление ошибки или успех рабочего запуска.

Общие границы доступа и язык общения — GIGACODE.md. Все правила этого разбора находятся
здесь. Разбор сам не разрешает настройку, исполнение или изменение определения:
покажи выводы и конкретный следующий шаг; агент продолжает только явно порученное. Неизвестное подключение не выбирай по списку серверов.

## Порядок разбора

Не требуй от человека технических команд, ручной фиксации сбоя или сбора журнала.
Повод для разбора — ошибка исполнителя, сообщение «не работает»/«результат неправильный»
либо просьба объяснить выполнение. Для жалобы на текущий результат используй точный
output из ответа исполнителя. Если запуск не определён однозначно, уточни, какой
результат имеется в виду; не подставляй последний запуск другого процесса.

До чтения метаданных, событий или результата Run проверь доступ публичной командой:
node tools/kit.js run diagnose <spec.json> с {"output":"<точная папка выбранного запуска>"}.
Создай spec через JSON.stringify/json.dump в уникальном файле системной временной папки
и удали его после команды, включая ошибку. Используй возвращённый reportFile.
Если этот допуск уже успешно выполнен для выбранного output в текущей области владения
в этом разборе, используй переданный reportFile. Сам по себе путь к файлу не подтверждает
прав. При отказе владения или неизвестном владельце верни blocked, не читай Run вручную
и не собирай обходной отчёт. Для ошибки до создания Run используй только переданные факты.

После успешного допуска сопоставь ожидаемый результат с выбранным запуском: читай
только относящиеся к проблеме события, результат, определение и контракт действия.
Не запускай процесс повторно ради диагностики. Неверный результат после completed
не переводит запуск в failed; расхождение объясни отдельно. Категория сбоя не доказывает причину.
Для этой операции не требуются настройка my, доступ к системам или перевод completed в failed.
Если журнала нет или файл не создаётся, сообщи ограничение; не придумывай события и
не составляй замену из переписки. Переписку и технические запросы не собирай и не очищай
для экспорта: diagnose сохраняет только предусмотренную инструментом проекцию событий.

Сообщи, что подтверждено, что лишь предполагается и что нужно для продолжения.
Если нужно уточнение, запроси конкретный пример расхождения: что ожидалось и что
получилось, а не «пришлите больше информации». Используй уже названный пример;
не проси повторять весь запрос или собирать технический журнал. Необъяснённый термин
из служебных событий замени понятным описанием того, каких данных не удалось получить.
Если причина понятна, объясни её и конкретный следующий шаг. Если сведений недостаточно,
сам предложи файл для разработчика и покажи полный путь: человек только решает,
передавать ли его. Сам ничего не отправляй и не проси переслать всю папку запуска.
Разбор не разрешает менять tools/, tests/, процесс или подключения; исправление и
повтор выполнения согласуются отдельно. При неизвестном исходе внешнего изменения
не повторяй его. Проверку реализации и тесты оставь отдельной задаче разработки.

Ошибку подключения связывай только с подтверждённой записью connections и её
adapterFile/mcpServer. Наличие нескольких серверов в settings не выбирает один из них.
Если не известен сервис, спроси, какое подключение вернуло ошибку; не называй Jira,
имя секрета или ключ по догадке.

- Секрет действительно отсутствует: укажи известные имя/ключ хранилища GigaCode;
  попроси ввести секрет в клиенте и перезапустить его.
- HTTP 401: авторизация не принята. Проверь соответствие выбранной учётной записи,
  сервера и секрета; это не доказательство единственной причины «токен устарел».
- HTTP 403: сервер отказал в доступе. Нужна проверка прав и политики доступа у владельца
  системы; не обещай, что замена токена исправит отказ.
- Таймаут/ошибка сервера: сообщи о недоступности, не об отсутствии секрета.

Токен из чата не используй. Секреты вводятся только в клиенте, не в чат и не в файлы.
