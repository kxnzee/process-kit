# Методы сверки: как раздел методики сопоставляется с параметрами процесса

Каждый метод возвращает одну запись сверки по разделу. Источник расхождения ищется
по значению с обеих сторон, а не по номеру строки: у методики и у процесса своя раскладка.

| Поле записи | Что это |
|---|---|
| `section` | раздел методики, как он назван на странице |
| `target` | где в процессе лежит сверяемое значение (например, `params.lookBack`) |
| `status` | `сопоставлено` / `разошлось` / `не проверено` |
| `process` | фактическое значение в процессе |
| `method` | фактическое значение в методике |
| `action` | что сделать: `изменить`, `выяснить`, `оставить` |
| `reason` | причина, когда статус не `сопоставлено` |

Решения владельца уровня по конкретному процессу берутся из файла по параметру
`methodologyNotes`: методы и общие правила здесь, частные снятия и принятые расхождения —
там. Один метод не знает, для какого процесса он исполняется.

Общие правила для всех методов:

- сравнение идёт по существу: регистр, падеж и вид глагола, «ё»/«е», лишние пробелы
  и порядок строк расхождением не считаются; расхождение — это разные статусы, разные окна,
  разные числа, разные условия;
- частичное совпадение — это `разошлось`, а не `сопоставлено`: в методике пять кодов КЭ,
  в процессе три → два расхождения с названными кодами;
- значения, которые по решению владельца уровня задаются вручную и заведомо шире методики,
  помечаются `оставить` с причиной, если методика объясняет, почему так бывает;
- методика — источник правил, но решения владельца процесса старше, когда методика прямо
  допускает исключение. Такое совпадение по сути — `сопоставлено` с пометкой в причине;
- если методика описывает значение словами («за неделю», «с понедельника следующей недели»)
  и одновременно даёт формулу, в `method` пишется формула, а словами поясняется в `reason`:
  слова оставляют свободу в датах, формула нет.

## `list-diff` — списки значений

Применяется к категориям статусов, перечням типов задач, меткам исключений, кодам КЭ.

1. Собрать список значений методики из её раздела: названия статусов, имена типов, коды.
   Заголовки подразделов в список значений не попадают.
2. Собрать список процесса из параметра.
3. Сравнить после нормализации. Записать `process` — значения только из процесса,
   которых нет в методике; `method` — значения методики, которых нет в процессе.
4. Оба списка пусты — `сопоставлено`. Один непустой — `разошлось`, `action: изменить`.
5. Список методики не удалось собрать (раздел назван иначе, страница без таблицы) —
   `не проверено` с причиной, а не «совпало».
6. **Значение методики, которого нет на инстанции.** Если значение из методики отсутствует
   в процессе уже осознанно — оно снято по решению владельца уровня и об этом есть запись
   в файле решений (`methodologyNotes`, вид `снято-по-решению`), — это не «методика
   неверна» и не `разошлось`: статус `сопоставлено`, `action: keep`, а причина — «значения
   нет на инстанции, снято по решению владельца процесса».
   - Запись годится только с подтверждением от системы: значение проверено живым обращением,
     и система его отклонила (для Jira — ответ 400 «The value '…' does not exist for the
     field '…'», весь запрос с несуществующим значением отклоняется целиком); дата проверки —
     в записи. «Так, наверное, нет» подтверждением не считается.
   - Нет подтверждения или записи нет — прежний порядок: значение идёт в `method` и делает
     раздел `разошлось` либо `не проверено`.
   - Такие значения перечисляются в `notes` артефакта сверки одним списком с указанием,
     что именно отвергла система; в `notInProcess` они не попадают — они разобраны,
     а не забыты.
   - Снятие действует только для своей системы и своего процесса: та же методика в другом
     процессе, где значение используется, по-прежнему даёт расхождение.

## `set-match` — отображения и признаковые поля

Применяется к отображениям «поле → идентификатор» (имена и коды полей задачи), к признакам
да/нет, к перечням типов связей. Сверяется наличие каждой пары и отсутствие лишних; для
двух инсталляций одной системы — что значение сверяется по каждой записи подключения
отдельно, а не по одной общей (код поля в разных инсталляциях различается).

## `rule-apply` — правило методики на выборке процесса

Применяется к правилам, которые «на глаз» не проверить: какие задачи исключаются, как
разделяются пустой релиз и технический релиз, куда публикуется отчёт. Метод берёт правило
из методики и проверяет, что оно **выразимо** параметрами и правилами процесса: есть ли у
правила нужные данные (поле, признак, адрес), и не записано ли в процессе другое правило
под тем же названием. Проверяется запись правила, а не пересчёт данных: пересчёт — дело
шага выборки.

## `window-match` — периоды и окна

Сверяется каждое окно (текущие поводы, планы): границы и то, от какой даты считается. Окно
методики, которого в процессе нет, — `разошлось` с `action: выяснить`: это может быть
намеренно не поддержанный режим. Если методика даёт и слово, и формулу, а процесс — третью
границу, в `process` и `method` пишутся обе фактические границы, а решение владельца уровня
о ширине окна идёт в `reason` и в `notes`.

## `alias-check` — синонимы и варианты написания

Для меток, статусов и названий типов сверяется, что синонимы из методики (`Release 2.0`,
`Release2.0`, «релиз») не ломают сравнение в процессе. Если процесс сравнивает строки
строго, а методика обещает регистронезависимость, — `разошлось`, `action: выяснить`.

## `path-match` — пути артефактов

Пути сравниваются по хвосту: путь из методики совпадает с путём процесса, если покрывает
названную структуру. Подстановочные знаки, паттерны ветки и примеры файлов путями не
считаются.

## `manual-note` — методика против ручного решения владельца

Применяется к значениям, которые в процессе шире методики по решению владельца (форма
отчёта, лишний раздел, иной адрес публикации). Если методика такого не требует, но и не
запрещает — `сопоставлено` с причиной «шире методики: решение владельца процесса». Если
методика прямо запрещает — `разошлось`.

## `unverified` — проверить не удалось

Раздел методики не найден, страница не дочитана, значение описано словами и не выводится
однозначно, условие автор сценария оставлен на обмозгование, оно считается на стороне
внешней системы и здесь не воспроизводится. Все такие разделы идут в итог с причинами.
«Не проверено» не равно «нет расхождения».
