# Состояние → одна ветка → возврат

Вход от диспетчера: исходная задача, personal-only/live, выбранный процесс при наличии,
ответы и согласия. Возврат: personalReady, отдельно connectionsReady только для
проверенного доступа, изменения, препятствие и ближайший шаг.

1. До плана настройки и вопросов выполни `node tools/kit.js setup-status`.
   Это безопасное локальное чтение фактов, без сети, записи и сырых ошибок.
   Не подменяй результат памятью или чтением повреждённого конфига в чат.
2. Выбери одну ветку по personal.state:

   | Состояние | Следующее действие |
   |---|---|
   | ready | Сохранить известные выборы; настраивать только нужные подключения |
   | missing | Для новой копии читать references/create-personal.md |
   | invalid, incomplete, outside-personal | Читать references/repair-personal.md; не пересоздавать копию |
   | unknown или команда не дала результата | Объяснить препятствие, остановить настройку |

3. Для ready при вопросе о требованиях без записи: кратко сообщи, что уже готово,
   назови нужные источники по выбранному процессу без анкеты полей. Верни nextQuestion
   только о первом недостающем подключении: какая система и какой проект. Адрес,
   способ доступа и следующий источник уточняются после ответа, если они неизвестны.
   Не загружай инструкции новой установки и изменения подключений ради объяснения.
   known.team=without-team — сохранённое «без команды», не отсутствие ответа.
   Известные профиль, команда и хранение не спрашиваются заново. Критерии отчёта
   не являются настройкой личной команды; заданные процессом правила не требуют подтверждения.
4. Для согласованного изменения подключений читай только references/connect-existing.md.
   Для сохранения пожелания нужна готовая личная копия и явное согласие: простую
   настройку запиши в config/my/config.json.preferences, развёрнутое правило — в
   context/my/<тема>/CONTEXT.md с областью и датой. Не дублируй; новый контекст применяется
   только по явной ссылке. При отсутствии личной копии верни необходимость personal-only.
5. После изменений перечитай setup-status; проверка и сохранение — references/save-settings.md.
   При personal-only не проверяй неизвестные будущие системы. Объявленные подключения
   не означают проверенный доступ. Верни факты и nextQuestion диспетчеру, не вызывай
   соседние скиллы. При повреждённой настройке ближайший шаг — проверка/восстановление
   конкретной проблемы, а не сбор всей анкеты подключений или получателей письма.
