# Продолжение пользовательского поручения

Это подробная policy-driven инструкция, не программный маршрутизатор. Обязательные
инварианты находятся в GIGACODE.md; здесь — случаи изменения, отмены и композиции.
Не создавай обязательный JSON, дополнительный LLM-вызов, журнал или State Machine runtime.

## Event и Intent

Event — отношение фрагмента реплики к поручению; Intent — тип работы. Ответ обычно
наследует намерение текущей задачи. Это словарь для рассуждения/приёмки, не закрытая схема.

| Event | Смысл |
|---|---|
| new_task | Новое поручение |
| answer | Ответ на однозначно ожидаемый вопрос |
| modify | Изменение условий или части результата |
| cancel | Остановка названной работы |
| status | Вопрос о фактическом ходе |
| feedback | Замечание к выбранному результату |
| other | Побочный вопрос, приветствие или неясная связь |

Intent: consult, execute, create, modify_definition, configure, diagnose, promote.
Не всякий execute требует Process, не всякий consult требует Mentor. Изменение периода
запуска не означает modify_definition. Не сопоставляй каждый Intent одному skill.

Одна реплика может содержать несколько Event и Intent для разных частей поручения:
«Не отправляй письмо, объясни отчёт и создай черновик похожего процесса».
Сначала учти запреты новых эффектов, затем изменения и зависимости. Разрешение одной
части не распространяется на другие; несколько частей не требуют параллельного исполнения.

- «Да» применимо к конкретному ожидаемому вопросу. При неясном предмете уточни его.
- «За прошлую неделю» — ответ или изменение периода текущей задачи, не новая цель.
- «Не нужно письмо» обычно меняет часть результата, не отменяет весь отчёт.
- «Не нужно» в ответ на предложение не обязательно отменяет исходную задачу.
- «Да, запускай» не заменяет verifyApproval защищённой операции.
- После побочного обсуждения старый вопрос может стать неоднозначным; не применяй ответ вслепую.

## Состояние поручения

Idle — отсутствие поручения. Active — можно работать; awaiting_input — нужен ответ;
blocked — есть проверенное препятствие; completed — поручение завершено в своей области;
stopped — новая работа после отмены не планируется. У blocked может быть ожидаемый вопрос.
Это описания в диалоге, не новые статусы Run Journal и не обязательный статус каждого turn.

| Ситуация | Поведение |
|---|---|
| Ответ на ожидаемый вопрос | Проверить значение и продолжить ту же цель |
| Ответ без ясного вопроса | Не угадывать разрешение; уточнить существенную связь |
| Изменение до start | Обновить требования и план |
| Изменение после start | Не менять сохранённые параметры; проверить допустимость нового запуска |
| Отмена | Прекратить новые действия в названной области после получения сообщения |
| Status | Получить факты, не выполнять следующий шаг и не делать новый start |
| Blocked + «готово» | Проверить устранение препятствия, не объявлять успех по слову |
| Completed + feedback | Diagnose результата без изменения completed на failed |
| Stopped + «продолжай» | Выяснить объект и состояние; не повторять неизвестный эффект |
| Побочный вопрос | Ответить и сохранить цель; явно остановленное не возобновлять |
| Новая задача | При явной замене переключиться; при существенном конфликте уточнить приоритет |

Не теряй цель и файлы, но не возобновляй явно заменённое поручение автоматически.
Очередь задач, taskId и постоянный журнал не нужны. Несколько неясных объектов
продолжения требуют уточнения, а не подстановки последнего запуска.

## Продолжение между способностями

Сохрани цель, этап, параметры и происхождение существенных значений, решения,
область согласия, завершённые операции, пути, препятствие и следующий шаг.
Секреты и вся история не копируются. Вспомогательная операция не завершает поручение.

Create Process → сохранить continuation → применить Create Action → проверить результат →
продолжить Create Process. При blocked/cancelled/failed зависимую часть не продолжать;
без новых фактов не повторять отказ. Уже созданное не удалять автоматически.
Применение skill — работа агента по инструкции, не гарантированный RPC хоста.

После потери диалога создание восстанавливается по файлам с указанием неизвестного.
Файл не доказывает прежнее согласие или публикацию. Run восстанавливается только
через Controller: recover/next, исходный attemptId и сохранённые параметры.

## Остановка и гарантии

Поручение, Run и исход эффекта различаются. Runtime сохраняет running/completed/failed;
не добавляй paused/cancelled/stopped или run cancel. Окончательная безопасная остановка
использует существующий fail; он терминален. Ожидание с намерением продолжить сохраняет
проверенный checkpoint, без ручного изменения state. Для pending act fail требует
проверенного not-applied; при неизвестном исходе Run может оставаться pending/running,
хотя поручение остановлено. Не подделывай закрытие и не повторяй эффект.

Хост может доставить сообщение после завершения инструмента. Не обещай прерывание
выполняющегося вызова или откат эффекта. Без перехвата всех сообщений и доверенного
состояния инструкции не обеспечивают принудительную State Machine. Проверки остаются
в существующих программных точках входа.
